# 以显式问题区分 Artifact 下载与理解

统一读取工具使用 StraviaRead 入口。输入 Artifact Reference 时，默认返回临时签名下载地址与文件名、MIME 等文件信息；只有在引用 URL 中显式提供 `question` 查询参数时才调用 Media Understanding，例如 `https://stravia/artifact/xxxxx?question=xxxxxxxxxx`，不使用独立的工具参数字段承载该问题。不因文件 MIME 为图片而自动启动模型调用。文件类型尚不受 Media Understanding 支持时，理解请求明确失败，但不因此禁止获取该文件的下载地址。

该规则解决“Artifact 引用返回下载地址”与“图片调用理解”的重叠，避免仅想下载文件的客户端意外触发模型调用。代价是 Artifact 的内容理解必须在引用 URL 中明确提供问题，不能仅靠媒体类型推断意图。`question` 表达读取意图，不改变 Artifact 身份；两条路径均沿用 Artifact 的 Principal 鉴权边界。

## 工具改造范围

内部 Agent 使用的搜索与网页抓取工具也纳入本次工具接口改造，不沿用“仅统一外层入口、内部工具接口保持不变”的建议。网页抓取同时提升为客户端可调用的工具能力，不再仅作为内部 Agent 的隐藏能力。

## 统一入口与执行层级

客户端、外层模型与内部 Agent 均使用 StraviaRead 入口，但搜索执行层级由平台固定的调用环境决定，不允许模型通过参数自行选择。客户端或外层模型提交 `query://` 时执行完整 Web Search，返回 Search Report；搜索 Agent 内部提交 `query://` 时只执行基础检索，不再次启动研究 Agent。网页 URL 在上述环境均进入网页抓取并返回 Markdown，使客户端也能直接读取网页。

各调用环境注入与实际执行层级一致的工具描述，明确提供研究回答还是基础检索。统一名称和输入形式不意味着共用无上下文的全局执行器：内部检索与外层研究仍保留不同的执行身份和结果契约，以避免 Web Search 通过内部 StraviaRead 递归启动自身。

本决策部分取代 ADR-0017 对内部搜索与网页抓取 wire name 的约定，并扩展网页抓取的客户端可用范围；保留其公开研究与内部基础检索必须区分身份和 owner 的约束。

## 统一入口下的能力授权

网页读取不新增平台开关，与 Web Search 共用现有“联网搜索”开关，取代此前独立开关的方案。该开关同时控制 `query://` 搜索与网页 URL 读取；Artifact 引用 URL 带 `?question=...` 时受 Media Understanding 开关控制，Artifact 下载只按 Principal 归属鉴权，不依赖这些能力开关。

保留现有联网搜索开关状态：开启的实例同时开放网页读取，关闭则两者均不可直接调用，不另设网页读取默认值或同步机制。内部基础抓取仍属于已获准执行的 Web Search。工具描述仅介绍当前调用方可用的能力，执行时仍须检查实际分流对应的授权，不能靠隐藏描述代替鉴权。

该选择避免增加设置；代价是无法单独关闭网页读取而保留搜索，或反向组合。透明注入也共用同一个“联网搜索”选择项，选中即同时包含搜索与网页读取，不新增网页读取勾选项。内部 Web Access 配置与基础抓取执行器不形成另一套公开授权入口。

## URL 参数的解释边界

平台仅对 Artifact Reference 解释 `question` 查询参数。外部 URL 的查询参数完整保留，不将其中同名的 `question` 当作平台指令，也不擅自剥离或改写；外部网站可能拥有该业务参数，签名资源地址也可能依赖这些参数校验签名。对外部图片提出指定问题时，先收存并取得 Artifact Reference，再通过该引用附加 `?question=...` 发起理解。

## 外部图片的默认理解

StraviaRead 直接收到外部图片 URL、没有指定问题时，先将图片收存为 Artifact，再调用 Media Understanding，默认任务为描述图片内容并提取其中可读文字。这不同于裸 Artifact Reference 的默认下载行为；对 Artifact 提出指定问题仍使用引用 URL 的 `question` 查询参数。

该路径受 Media Understanding 的平台开关与本次工具暴露范围约束；能力关闭或图片格式不受支持时明确失败，不改用其他能力。收存遵守 ADR-0049 的 Principal 归属、网络访问、大小与存储失败边界，不因输入来自统一读取工具而绕过文件准入规则。

## 普通文件 URL

StraviaRead 收到 ZIP 等既非网页、也非图片的普通文件 URL 时，将文件收存为 Artifact，返回 Artifact Reference、文件名、MIME、大小与临时下载地址，不擅自解析文件内容、自动解压、执行文件或调用模型。该路径沿用 ADR-0049 的文件准入与保留规则，以及 ADR-0050 的下载交付策略。

普通文件收存不是理解失败后的降级路径。已经明确请求理解，但能力关闭或格式不受支持时仍明确失败，不以返回下载信息冒充完成理解。

## 按能力透明注入

API Key 的透明注入沿用“联网搜索”与“多模态理解”选择项，不改为整个 StraviaRead 的单一注入开关，也不新增网页读取选择项。“联网搜索”同时包含搜索与网页读取；客户端未显式声明工具时，平台将该 Key 选中且平台总开关已开启的能力合并为一个 StraviaRead 声明，各能力贡献与自身契约一致的简短调用说明。本次注入同时确定可执行能力范围；模型即使猜出未暴露能力的输入形式，也不得通过该注入入口执行它，不能仅靠省略说明限制能力。

透明注入选择是自动提供工具的偏好，不是 API Key 能力授权。客户端按平台约定显式声明 StraviaRead 或通过 MCP 直接调用时，可使用平台总开关已开启的能力，不受该 Key 的自动注入选择限制；Principal、Artifact 归属及其他既有执行限制仍须检查。平台关闭的能力不能通过显式声明重新开放。

该规则保留“平台是否提供”“Key 自动注入哪些能力”与“本次工具暴露范围”的区别，避免统一工具名后意外自动开放所有能力。代价是执行层必须维护本次暴露范围，不能只注册一个无差别的全局 StraviaRead 执行器。

迁移保留现有联网搜索与多模态理解的勾选状态；原已勾选联网搜索的 API Key，在对应平台开关开启时，通过 StraviaRead 同时自动获得搜索与网页读取，不要求另行启用网页读取。

## 工具入口直接切换

Stravia 自有工具入口直接切换为 StraviaRead，不保留旧调用别名。新工具发现、新调用与内部 Agent 的工具声明使用新入口；原显式调用平台 `web_search`、`understand_media` 等旧入口的客户端须迁移工具名称与参数。旧历史记录原样保留，不因工具改名而批量重写；Provider 协议中的原生工具类型不属于此次平台工具身份迁移范围。

该选择避免长期维护两套公开调用契约，代价是旧客户端不能继续依靠原平台工具入口调用。本决策部分取代 ADR-0009 的公开 `understand_media` 工具身份与 ADR-0017 的公开及内部旧 wire name，不合并它们原有的能力执行 owner。

## 插件接入职责

插件贡献支持的输入领域、简短调用说明与实际处理入口，执行其拥有的搜索、网页抓取或多模态理解。StraviaRead 统一负责按明确规则分流、检查能力开关与本次暴露范围、解析 Artifact，并通过平台已有文件模块管理收存与签名下载；插件不复制这套公共文件与安全规则。

工具说明按当前可用能力拼接，不通过说明文本推断路由。内外搜索仍由平台确定的执行环境区分，不能因统一名称而递归启动研究。插件不得自行放宽 Principal 归属或联网限制；同一执行环境的输入领域出现无法消解的注册冲突时，明确报错，不以加载顺序决定接管者。

接入复用现有插件体系，不另建插件安装或加载系统。该选择让能力执行保留各自 owner，统一工具拥有公共分流与安全规则，代价是插件注册必须提供可判定的处理领域，不能仅提供一段自由文本简介。

本决策确认 Artifact 输入分流、外部图片默认理解、普通文件收存、URL 查询参数边界、工具改造范围、执行分层、能力授权、透明注入、直接切换及插件接入职责，不表示工具已经实现。
