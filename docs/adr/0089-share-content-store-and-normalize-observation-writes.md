# 共享正文存储、按引用回收依赖并规范化 Interaction Observation 写入

Turn Chain、History Marker 与 Interaction Observation 会遇到逐字节相同的思考、可见输出和工具正文，但它们记录的是不同事实。三方平等使用按 Principal 隔离的内容寻址存储，只共享正文，不共享含来源、可见性或签名的外壳。这样既去掉副本，也不让 Generation Chain 的正确性依赖 Observation 是否开启、写入成功或仍在保留期内。Marker 仍拥有隐藏载荷；Observation 不成为执行历史事实源。

## 分享字节，不分享所有权

正文边界按 Canonical Item 类型定义，不按 JSON 键名猜测，也不为短值另开路径；UTF-8 文本和 JSON 的身份区分格式。各方保留自己的外壳和引用；跨协议投影可以复用正文，但恢复保留当初交付的字节，不用当前渲染器重新生成历史。不同分支即使引用同一份正文，仍各自保留诊断收据。共享内容不靠租约或所有者身份判活，回收必须事务内重检所有引用；PostgreSQL 不用全表锁串行化内容写入与回收。

## 保留下限与引用各管一件事

历史保留天数给 Interaction、拒绝请求和 Turn 节点设定回收下限；Run 和事件随所属 Interaction 保留。子节点保护其祖先，Turn 节点原子登记所依赖的 Marker、凭据映射和 Responses 原生压缩记录，登记也保护来源节点。只让子节点保护祖先而不保护依赖，会留下能读却无法完整续接的历史。相比提交时逐一续期，本决定不更新祖先和依赖的时间，也不在调整保留设置时重写存量行。

常规到期由回收扫描落实，不在读路径上逐行判断。超过下限但尚未删除的历史仍可能续接或重新被引用；被引用的依赖不能先删。未引用的 Marker 与原生登记分别按自身发布或确认状态保留，以覆盖先交付、后提交或回传的情形；未发布或未确认记录有独立的短期限。凭据映射能否参与出站替换与其能否被删除是两件事，分别由[凭据保护设计](../design/credential-protection.md)和引用保留决定。候选来自跨过期限和失去最后引用这两个变化，删除前重检，而不是每轮重扫仍在使用的历史或在每次提交维护引用计数。

## 观测写入按执行阶段归并

事件记变更顺序，投影记状态，内容存储记正文；摘要可带引用，详情按需读全文，不用截断正文换取小摘要。围绕同一 Run 的执行阶段合并事务，避免每条诊断命令都同步一次 WAL，同时不延迟必须及时可见的阶段边界。不为减少提交引入跨 Run 等待窗口，也不降低数据库持久性来换吞吐。
