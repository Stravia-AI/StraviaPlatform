# 将显式媒体输入收存为 Artifact

Stravia 自动抓取并收存结构化媒体／附件字段中的外部 URL，以及明确交给文件上传／导入接口的 URL；普通消息文本中的 URL 不因出现于请求中而触发自动收存。收存的文件沿用 Artifact 的 Principal 归属边界，不建立另一套附件身份。

选择保存文件内容而非只保留外部 URL，是为了让后续文件使用与平台保留策略不依赖外部地址持续有效；代价是平台需要承担抓取与存储成本。自动收存范围限定为显式文件输入，避免把普通链接的引用或讨论误当作下载与持久化请求。

## 收存失败处置

需要收存的远程文件必须完成抓取与存储后，本次模型请求才可继续；任一文件收存失败，返回明确的附件收存错误，不启动模型调用。不得降级为向 Provider 透传原 URL，也不得忽略附件继续生成。文件上传／导入接口同样只有完成收存才能返回成功。该规则保证平台保存的文件与模型使用的内容一致，代价是即使 Provider 可以访问源 URL，只要平台无法完成收存，请求仍会失败。

## 外部文件抓取的网络边界

外部文件 URL 只允许公网 HTTP(S)，禁止 loopback、私网、链路本地、云元数据地址及非 HTTP(S) 协议。DNS 解析、实际连接与每次重定向均须遵守该边界，不能通过公网入口转向内网。平台自己的 Artifact Reference 在归属鉴权后直接通过 Artifact Store 读取，不进入外部 URL 抓取路径。

该限制沿用 Web Access 的公网访问边界，避免客户端利用文件收存探测平台网络或向 Provider 外传内网内容。代价是 NAS 等内网 HTTP 地址不能直接导入；客户端须自行读取本地或内网文件，再上传文件内容。

## 文件保留期刷新

Artifact 仅因所属 Principal 的鉴权使用刷新保留期：模型请求实际解析并使用文件（包括恢复历史附件）、Connect Client 通过 StraviaRead 鉴权解析文件，以及 Platform Tool 在所属 Principal 下读取文件。每次有效使用将文件保留截止时间延至本次使用时间加请求保留天数。

访问已签发下载地址、普通文本中提到 Artifact Reference、管理面查看日志或列出文件均不刷新保留期。文件保留期刷新不延长已签发的 Artifact Download Grant 或 Artifact Upload Grant；该边界避免持有泄露下载地址的人通过反复下载延长文件保存。

## 向 Provider 交付文件内容

按 ADR-0050 开启外部签名下载并配置文件公开访问地址时，优先使用 Artifact 的临时签名下载 URL；仅当目标协议无法表达该媒体的 URL 输入、但能够表达内联内容时，改用 base64。关闭外部签名下载时使用 base64，即使设置中保留了公开地址也不切换为 URL；目标协议无法表达该媒体的内联输入则明确失败。两种方式均无法表达时也必须明确失败，不得删除附件或自动改为文字摘要。

该选择在调用上游前依据协议的表达能力完成，不是运行失败后的重试策略。已经发送 URL 后发生抓取失败，不自动改用 base64 重跑模型请求，避免在执行状态不明时重复调用。公开地址配置决定首选交付方式，但不能赋予目标协议原本不具备的媒体表达能力。

## 媒体内容的持久化边界

结构化媒体／附件中的 base64 内容收存为 Artifact。平台所有持久化记录，包括历史、请求日志、Debug Trace 与诊断包，只保存 Artifact 引用及必要元数据，不重复保存媒体 base64；向 Provider 交付需要 base64 时，从 Artifact 内容生成。普通文本中看起来像 base64 的字符串不因其编码形态自动转为文件。

该规则覆盖 Wire Debug Capture，并部分取代其除凭据脱敏外保留正文的约定。诊断记录须明确标记媒体内容已外置，不能将替换后的内容宣称为原始 wire 字节。文件过期后，记录只能展示引用与元数据，不能继续还原媒体正文。选择统一外置是为了避免大对象在各持久化面重复保存；代价是媒体部分的诊断不再具有原始字节保真，且内容恢复受 Artifact 保留期约束。

## 文件大小与暂存限制

现阶段保留现有 Artifact 限制：单文件最大 100 MiB，每个 Principal 最多 16 个未完成且未过期的上传任务，合计声明文件大小最多 400 MiB。同一 API Key 的多个客户端共享该额度；一个文件的多个上传分片只计一个任务，上传完成后释放名额，已完成文件不占用此额度。达到上限时拒绝新建上传任务，不自动排队；放弃但尚未过期的任务仍占用额度，过期后不再计数。普通上传、临时上传授权、URL 收存与请求内 base64 附件均执行同一套适用限制，不因入口或内部／S3 存储后端不同而放宽。

base64 按解码后的文件字节数计量；URL 下载按实际接收量限制，不仅依赖 Content-Length。超限明确失败，不截断文件；Provider 自身更低的输入限制仍须遵守。该选择暂不为大音视频扩大单文件上限，超过 100 MiB 的文件仍拒绝；暂存限制不等于全部已保存 Artifact 的总容量限制。

## 已保存文件的总容量

平台不设置已保存 Artifact 的总容量限制，不增加实例级或 Principal 级长期存储配额；内部存储与 S3 均适用。此前确认的单文件大小与未完成上传额度继续保留，它们不是长期存储总量限制。文件按保留期管理，反复被有效使用的文件可以持续保留。

该选择避免新增总容量配置与容量满额准入规则；代价是平台不保证磁盘用量或 S3 存储费用有固定上界。底层存储空间不足、配额耗尽或写入失败仍作为真实收存错误处理，不能把未完成收存报告为成功。

## 保留期到期与物理清理

Artifact 保留期到期后停止接受新的引用使用，不允许通过访问复活，也不继续签发新的下载授权。物理删除与保留期到期分离：已经开始的平台读取允许完成，已经签发且尚未过期的 Artifact Download Grant 所需文件保留到授权到期，随后在不存在其他读取保护时清理。

这些保护仅延后物理清理，不刷新文件保留期或延长已签发授权。例如文件在 12:00 到期，但此前签发的链接有效至 12:10，则 12:00 后不接受新的 Artifact Reference 使用，已有链接仍可按原授权下载至 12:10。该选择避免清理破坏正在进行的读取或提前使有效链接失效；代价是物理内容可能短暂超过逻辑保留期。

## 既有记录不做媒体回填

媒体收存与持久化外置规则仅应用于新记录，不批量改写已有历史、日志或诊断记录，也不回填其中的媒体 base64。旧记录按原有保留规则自然过期；升级本身不续期、不提前删除旧记录，不重跑模型。

这是“持久化记录不重复保存媒体 base64”的明确存量例外：旧记录存续期间仍可能保留原媒体内容。旧历史被新请求使用而形成新记录时，新记录须遵守外置规则，但不因此改写原记录。该选择避免升级期间的大规模历史改写；不承诺在固定期限内清零旧 base64，旧记录的实际存续仍取决于其原有保留与续期规则。

本决策确认输入范围、收存失败、网络访问、保留期刷新、Provider 交付选择、媒体持久化、大小与暂存限制、不设长期总容量上限、清理协调及仅处理新记录的迁移范围，不表示相关行为已经实现。
