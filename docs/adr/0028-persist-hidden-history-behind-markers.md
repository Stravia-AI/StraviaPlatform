# Persist hidden history behind one-to-one markers

客户端看到的历史不应泄露平台工具执行或让外来推理签名冒充客户端协议的原生内容，但客户端编辑周边消息后，仍应能继续携带它选择保留的隐藏历史。为此用按 Principal 隔离、不可猜测的 History Marker 在客户端历史的原位置表示一个隐藏单元：一个平台工具的调用与结果，或一个受保护的 Thinking block。不以整轮为单位聚合，也不靠未编辑前缀、父链匹配或上下文猜测恢复。

History Marker Store 是隐藏载荷的权威来源；Generation Chain 留引用和自己的客户端投影，不复制隐藏载荷。Marker 在交付前持久化；恢复由客户端当前提交的公开历史决定，只在有效引用位置补回对应隐藏单元，不覆盖公开工具调用或结果。无法解析或无权访问的引用不发给上游；同一请求只展开一次，但不会跨分支消费引用。

## 取舍

- **不用跨请求保活的 Inference Run。** 客户端回传工具结果时启动新 Run，通过持久执行记录与已启动的平台工具会合。条件式认领防止多个实例同时执行；所有者失联时记录中断，不自动重放可能已有副作用的调用。客户端等待不是共享执行的所有权；后台交接以持久提交为界，不把交付 Marker 当作已完成交接的证据。
- **不为 Marker 缓冲整个模型轮次。** 按已知内容边界封存隐藏单元；回传引用缺失时不猜测重建。持久化失败若发生在流提交之后，只能通过该协议的流终态报告；已执行的外部副作用不因断线撤销。
- **只降级出口表示，不改写权威历史。** 路由暂时无法回放签名或密文时仍保留可读推理，且不销毁原载荷；切回兼容出口仍可回放。Marker 不是解密机制。具体载体、可回放范围和拒绝处理由[架构设计](../design/architecture.md)拥有；[Agent Core](../design/agent-core.md)定义执行交接，[数据布局](../design/data-layout-performance.md)定义引用保留与正文共享。
