# 按字段固定 Provider Model 规格的人工修改

本决策部分取代 [ADR-0054](0054-persist-provider-model-snapshots.md) 中“编辑即由管理员接管整条规格”与“显式重新导入整条 Provider Catalog Entry”两项约定，并删除 [ADR-0057](0057-own-provider-write-and-route-bind-as-two-modules.md) 中的 Provider Model reimport 操作；快照持久化、有效模态回退、输出资格与 Effective Availability 的约定不变。

管理员通常只修正个别字段（例如补一个缺失的缓存价格），整条接管却让其余字段从此错过上游的改价与规格更新，而成本估算直接依赖这些价格。因此 Stravia 改为逐字段记录人工修改：管理员修改过的字段被固定，普通同步只更新未固定的字段；每个已固定字段可单独恢复同步。

为保留 ADR-0054 选择快照而非稀疏覆盖的主要收益，合并发生在写入时：Provider Model 仍只持久化一份生效规格供所有读取方使用，另存已固定字段集合，以及每个字段最近一次同步得到的来源值。来源值随每次成功同步更新，无论该字段是否固定。恢复同步即用已保存的来源值写回该字段并取消固定，不发起上游或目录请求；来源中没有该字段时，恢复后为未登记。

字段粒度与编辑器控件一致：名称、上下文长度、最大输出、输入模态、输出模态、推理强度列表与各能力开关各为一个字段；价格的输入、输出、缓存读、缓存写各为一个字段；上下文分档整体为一个字段。管理写入以字段为单位提交，请求中出现的字段即被固定，即使其值恰好等于来源值；是否固定从不由字段值与来源值是否相等推断。没有同步来源的手动 Provider Model 与纯本地设置（如峰谷定价）不提供恢复同步。

## Considered Options

- 保持整条接管：实现最简单，但一次小修正会让整条规格停止跟随来源，价格变动尤其容易过期。
- 读取时合并来源值与人工值（ADR-0054 否决的稀疏覆盖）：每个读取方都要同时处理两份事实与合并规则。
- 迁移时按值比较，只固定与来源不同的字段：属于按值推断人工修改，并会放开管理员有意填成与来源相同的值。
- 以“全部恢复同步”替代整条重新导入：逐字段恢复已能表达意图，删除整条操作以避免两条并存路径。

## Consequences

- 既有 `edited` 快照迁移为全部字段已固定，行为与迁移前一致，管理员按需逐字段恢复同步；`imported` 快照迁移为没有固定字段；`unregistered` 快照没有来源值。
- 删除整条重新导入的管理接口与界面入口，不保留别名。
- 同步或恢复同步改变推理强度列表时，关联 Target 的 Generated Mapping 在同一事务内重新计算；Overridden Mapping 的保留规则与 Thinking Control 可写性校验不变。
- SQLite 与 PostgreSQL 都要新增已固定字段与来源值的存储，并重新生成参考 schema。
