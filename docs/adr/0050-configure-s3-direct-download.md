# 允许通过开关选择 S3 直连下载

Artifact 上传与引用接口保持统一，下载交付允许使用存储后端的原生签名地址。仅设一个“外部签名下载”开关，同时决定 Provider 的文件交付方式与 StraviaRead 返回给客户端的下载去向，不再另设 S3 直连开关。下载方式不改变 Artifact 的归属边界。

未配置外部 S3 时默认使用内部存储。上传接口保持现有契约，不因内部存储与外部 S3 的实现差异而改变客户端调用方式。

允许直连是为了利用云存储的下载能力，减少 Stravia 的下载带宽和连接开销。设置必须明确提醒管理员：开启后，实际下载方（Connect Client、Provider 等）必须能够直接访问 S3 下载地址；能够访问 Stravia 不代表能够访问 S3。直连仍使用临时签名授权，不要求把 S3 存储桶设为公开。

## 下载入口的手动配置

“外部签名下载”默认关闭，配置 S3 不自动开启。存储配置仅决定文件的存放后端，不证明客户端或 Provider 可以直接访问该后端；管理员须主动开启签名下载模式。默认状态下，Provider 使用 base64，客户端仍可通过平台签名链接下载内部存储或 S3 中的文件。

客户端下载入口提供 UI 手动配置能力；初始化时以前端感知到的域名预填设置，管理员可以修改。前端感知到的地址只提供初始化默认值，不构成 Provider 能够访问该地址的证明。

客户端访问地址保存后始终以配置为准，直到管理员手动修改，不根据后续请求的 Host 或转发头自动改写。配置保存完整入口，包括协议、端口及必要的部署路径前缀；生成上传命令及使用客户端入口的下载链接时均使用该地址。多入口部署由管理员选择实际客户端可达的入口，平台不按每次请求自动切换；开启外部签名下载后的链接仍按文件公开访问地址或 S3 地址规则生成。

只有开启“外部签名下载”后才要求填写文件公开访问地址。启用时，内部存储自动带入客户端访问地址，S3 存储自动带入 S3 地址；该规则替代此前依据客户端地址是否为公网 IP 进行自动预填的方案。自动带入地址不证明实际下载方可以访问该入口。

## Provider 下载链接与最低剩余有效期

开启外部签名下载后，内部存储向 Provider 提供平台签名下载 URL，S3 存储直接提供原生 S3 预签名 URL，不先经过平台重定向。地址必须使用实际下载入口正确签名，不能把平台接口路径拼到 S3 地址上，也不能在签名后任意替换域名。该规则保留 ADR-0049 已确认的协议表达能力例外。

每次向 Provider 发起调用时，交付的远程签名下载 URL 必须至少还有 5 分钟有效期；重试及后续 Model Turn 同样适用，不能仅在链接最初生成时满足该条件。该约束针对平台生成的下载链接，不承诺延长客户端提交的外部源 URL；外部源文件仍须先按 ADR-0049 完成收存。

签名下载链接默认自签发起有效 15 分钟。实际发起 Provider 调用前，剩余有效期不足 5 分钟时重新签发，仍满足要求时可以复用；排队、工具执行等耗时不豁免发送时检查。重新签发产生新 URL，不延长旧 URL 的有效期，下载授权与上传授权的有效期分别管理。

S3 链接的有效期还须受签名凭据自身到期时间约束，不能仅依据 URL 声明的期限判断。无法生成至少还有 5 分钟有效期的链接时明确失败，不向 Provider 发送即将失效的地址。

## 统一开关与客户端交付

| 外部签名下载 | 向 Provider 交付 | StraviaRead 向客户端交付 |
|---|---|---|
| 关闭 | base64 | 客户端访问地址下的平台签名链接；Stravia 从内部存储或 S3 读取并流式返回文件 |
| 开启，内部存储 | 文件公开访问地址下的平台签名链接 | 文件公开访问地址下的平台签名链接 |
| 开启，S3 | S3 原生预签名链接 | S3 原生预签名链接 |

Provider 交付仍保留 ADR-0049 的协议表达能力例外。关闭开关不禁止客户端下载；该模式让客户端下载经过平台，并且不向 Provider 提供文件下载 URL。开启 S3 模式则直接交付 S3 预签名地址，不要求先经过平台重定向。

选择统一开关是为了避免多个下载开关互相制约；代价是不提供“Provider 使用 base64，同时客户端直接下载 S3”的独立组合。

本决策确认统一下载开关及其默认关闭状态、按存储后端预填公开入口、保存后固定使用完整客户端地址，以及签名下载交付与有效期规则，不表示相关行为已经实现。
