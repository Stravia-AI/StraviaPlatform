# Vendor Plugin 获得连接范围的凭据信任

管理员选择 Vendor Plugin 并为其连接登录或填写凭据，即授权该插件处理本连接的上游账户秘密，包含必要的 OAuth token 交换、响应解析、认证编码与刷新，不要求逐次确认。连接尚未保存时，授权限定于对应的待配置连接认证会话；安装插件本身不授予所有连接的凭据访问权。

这一取舍允许 Devin 等插件完整拥有自定义 OAuth 交换与 protobuf 认证编码，而不把供应商特有逻辑重新放回宿主。凭据持久化、连接与认证会话归属、跨连接访问隔离仍由宿主拥有；插件不能访问其他连接、其他认证会话或 Stravia 平台凭据。共享同一插件代码不意味着不同连接共享凭据或敏感运行状态。

不采用“所有凭据永远对插件不可见”的约束：通用 header 注入不足以表达自定义 token 响应解析及请求体认证。Wasm 限制插件访问宿主的能力，但不能保证插件不会滥用已授权读取的秘密；诊断脱敏也不能替代对插件实现的信任。

本 ADR 记录已确认的目标信任模型，尚不表示实现已完成。第三方分发与来源验证、网络授权细则、插件升级时的授权继承另行决策，不由本决策隐含批准。
