# 冻结双币种金额，以首次汇率换算设定前的历史

管理员可以在美元之外定义一种自定义币种，用量分析在设有自定义币种时以它展示，同时历史计费不能有任何变动。因此每笔按量成本与计费在发生时同时冻结两个金额：美元金额，以及按当时汇率折算的自定义币种金额。价格按填写时的币种保存，以该币种计算的一侧是精确值，另一侧按当时汇率换算。修改汇率只影响此后的记录；更换自定义币种只改变显示符号，不换算任何金额；自定义币种一经设定不能删除。

首次设定自定义币种时，不改写已有的记录。设定时的汇率作为首次汇率单独保存且之后不变；设定之前只有美元金额的记录，一律以“美元金额 × 首次汇率”展示。统计桶分别累计自定义币种金额与“没有自定义币种金额的美元部分”，展示时后者乘以首次汇率。唯一需要换算的数据是各 API Key 的消费上限，按首次汇率在一个小事务内完成。

## Considered Options

- 只保存美元，展示时按当前汇率换算：实现最简单，但每次修改汇率都会改变历史计费的显示金额。
- 首次设定时分批回填历史记录的自定义币种金额：结果与按首次汇率换算相同，却要在运行时批量改写大量观测行，需要可断点续跑的在线任务，且长时间占用写锁；仓库没有这类先例。
- 允许删除自定义币种：已按自定义币种填写的价格、订阅价与消费上限都要换算回美元，换算结果取决于删除时的汇率。

## Consequences

- 订阅设置的每条生效记录同样在创建时冻结两种金额，订阅成本摊销不受之后修改汇率影响。
- 没有设定自定义币种时，只展示美元；设定后，消费上限与用量分析统一使用自定义币种。
- 今后若必须批量改写数据，遵循[架构 §10.1](../design/architecture.md) 的分批规则：每批独立提交并随批释放写协调，后批失败保留已提交进度并显式报错，不延长锁超时，也不自动重试。
