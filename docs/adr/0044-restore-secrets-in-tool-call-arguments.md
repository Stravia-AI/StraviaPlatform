# 可逆脱敏还原回答与所有工具调用参数

Stravia 在交付给请求方的回答文本、交付给客户端的公开工具调用参数，以及平台工具执行参数中还原当前 API Key 有权解析的秘密占位符。选择该行为是为了让工具透明使用真实凭据；只还原回答文本或仅允许客户端工具还原，会破坏平台工具使用真实凭据的流程，因此不采用。

## 往返流程

客户端以原有协议向 Stravia 提交明文用户消息、工具调用参数与工具结果，不负责生成或还原秘密占位符。可逆脱敏开启时，Stravia 在请求发送给模型 Provider 前识别并替换受保护模型文本中的秘密；Provider 接收替换后的内容。如果 Provider 在当前或后续轮次返回已有占位符，Stravia 按当前 API Key 的有效映射还原，再交付明文给客户端；不要求 Provider 每次返回占位符，也不要求 Provider 执行加密或解密。

该能力保护发给模型 Provider 的可读文本，不承诺阻止工具路径外传秘密。模型即使未见过凭据原文，也可能生成含占位符的 URL 或其他工具参数，工具在还原后可能把原文发送给第三方；这是已接受的安全边界，不表示放宽既有工具授权或出站安全控制。工具结果再次进入模型请求时仍属于受保护模型文本，必须重新脱敏。

## 无法解析的占位符

映射查询正常完成，但占位符不存在、已过期或不属于当前 API Key 时，保留占位符原样，继续交付回答或按既有授权执行工具；不猜测原文、不删除占位符，也不向调用方区分它是否属于其他 API Key。此选择优先保持请求连续性，接受回答中出现不可用配置、工具携带未还原占位符而失败或产生错误操作的风险。

这与脱敏处理故障不同：扫描、替换或存储访问本身发生错误时，仍按 ADR-0042 显式失败，不以“占位符不存在”为由吞掉处理错误。

## 关闭总开关

关闭可逆脱敏总开关只停止新模型请求的检测与替换，不删除已有映射；已有有效占位符仍按 API Key 边界在回答文本及所有工具调用参数中还原，直至过期。上游对话上下文可能仍持有旧占位符，同时停用还原会破坏既有对话与工具流程，因此不采用。

总开关不是立即禁止所有秘密还原的安全开关。管理界面必须明确说明关闭后不再提供新请求的脱敏保护，但旧占位符仍可还原，包括工具参数；ADR-0042 的故障策略仍适用于继续运行的还原处理。
