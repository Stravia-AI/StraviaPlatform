# 上游凭据拒绝时持久化标记 Provider 凭据失效

Provider 凭据失效是持久化的 Provider 级证据，不是 Target 熔断或管理员的启用开关。API Key 被上游明确拒绝时标记失效；OAuth 先使用既有恢复预算，只有明确拒绝授权、已拒凭据无可用恢复方式，或刷新后仍被拒绝，才标记。普通网络、限流、服务端或响应解析失败不能证明凭据失效。OAuth 最近一次刷新失败与 Provider 凭据失效是不同状态。

失效过滤新的 Target 选择，不中断在途请求或启动后台半开重试。新凭据或影响连接的配置变更、重连或刷新成功、明确验证凭据的已保存连接检查可以复位；仅访问到端点、通过本地配置校验、切换启用状态或检查草稿不构成复位证据。持久化结果按实际执行的连接代际和插件版本条件写回，旧结果不能覆盖已更新连接。

用熔断器表达失效会把持久授权事实混入按 Target 自动恢复的瞬态状态；自动关掉 Provider 则会覆盖管理员意图，故均不采用。证据分类、共享刷新与条件写回见 [Vendor Wasm 插件设计](../design/vendor-plugins.md)。
