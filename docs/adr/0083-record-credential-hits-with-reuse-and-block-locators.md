# 命中记录同时记录新增与复用，并携带块级定位

> Interaction 级聚合与 `kind` 筛选、复用作为列表行、占位符 `marker` 仅限 Debug Run、命中记录不保存可定位片段这几项已被 [ADR-0087](0087-list-credential-hits-per-mapping-with-retained-item-context.md) 取代。`credential_mappings_reused` 事件及其口径、`locators`、映射 `rule_ids` 与请求记录的块级高亮入口仍然有效；原文保留供追溯。

## 决定

凭据保护「命中记录」原先只投影映射新建事件，来源类型在 Interaction 内取并集，复用不留痕，因此回答不了「哪条消息里保护了什么」。现决定：

- 新增普通事件 `credential_mappings_reused`，载荷与 `credential_mappings_created` 同形，在已有有效映射被实际用到时发出：位于本次请求新提交的文本，或出现在模型响应的工具调用参数里；客户端重放的历史文本不写入。命中记录列表按 Interaction 聚合，新增与复用分开显示，时间取该 Interaction 在当前筛选下最近一次命中；复用不显示次数。
- 每个映射携带去重且有上限的 `locators`，逐项保存「规则 + 来源」配对，以及块级标识：工具参数与工具结果用 provider 原始 `tool_id`，用户消息只标记是否为最后一条用户输入，其余来源不带标识。不使用请求条目下标（`protect` 之前历史标记还原会拆分、注入条目），不保存字符偏移、消息片段或指纹。
- 请求记录从命中记录进入时，按 `tool_id` 与 Run 高亮命中块。解析不到的命中（来自更早的 Interaction、历史用户消息、system 与其他来源）只定位到 Run 并明确标注，不做块级高亮。
- 映射表新增 `rule_ids`（JSON 数组文本），在创建映射时写入检测出该秘密的全部规则，之后不改写。复用命中的位置取自出站时实际发生的替换和响应里实际发生的还原，规则取自映射自身的归因：已知凭据出现在检测器认不出的上下文（例如只有裸值的工具结果）也能记录，模型输出里只有引用的工具调用参数也能归因。迁移前创建的映射规则为空，只受保护，不产生复用记录，也不回填。
- 删除管理接口的页面级 `observation_gap`，其限制说明移入「保护详情与限制」。
- Debug 开启的 Run 中，两类事件的每个映射额外带占位符标记 `marker`，使上游 wire 里的标记能对应回规则和来源。Debug 关闭的 Run 不带；命中记录列表接口永不返回标记；不记录明文。

## 取舍

- 复用只记「本次新提交」的位置：最后一条 Assistant 之后的条目（新用户消息、工具结果）；更早的条目是客户端重放的历史，已在首次出现的那一轮记录过。没有 Assistant 条目时整个请求都是新输入。指令、工具定义、元数据与供应商整请求副本每轮都会重发且无法单独判定新旧，有历史时一律不记复用。这样记录回答「这个凭据在哪里被用到」，写入量随新输入而不是随会话长度增长。
- 新旧按请求自身的结构判定，不用 Generation Chain 的输入 delta：delta 在 Hook 之后重新物化、压缩后重新切分，引擎也无法把它对应回受保护请求里的条目。代价是已有历史会话中首次出现的已知凭据在重放历史里不记。新增发现不受影响：映射刚建立，首次出现不是重放，仍记录它出现过的全部位置。
- 模型自己产出的工具调用参数不等到下一轮重放才记，而在响应还原时记一次，来源 `tool_arguments`，块标识是该调用 ID；下一轮重放它则是历史，不重复。只看完整响应，流式中途断开而没有完整响应时不记。模型在同一轮就把刚新建的凭据用到工具调用里时，该 Interaction 同时有新增与复用，这是如实的：凭据先出现在消息里，随后被用在调用里。
- 规则存在映射上而不是每次重新检测：出站时已知凭据未必再被检测器命中，模型输出里的引用更没有检测上下文。代价是一张表加一列（SQLite 与 PostgreSQL 各一个迁移），以及规则集之后变化时，映射仍沿用创建当时的归因。
- 选择「事件加字段」而非给 Debug Trace 新增语义记录类型：后者违背 [ADR-0063](0063-record-four-direction-wire-debug-at-transport-boundaries.md) 的「Debug 只保存四方向 wire」，且只有写入 Trace 文件才能安全承载明文，而明文并无必要。
- `marker` 是对「事件不含可恢复引用」的有意例外，限于 Debug 开启的 Run；它不含秘密，持有它也不能脱离对应 Principal 的有效映射还原。
- 块级而非字符级高亮：提取偏移相对于提取文本（含上下文前缀、已解码的工具结果），与 Observation 里存储的 JSON 与渲染后的 Markdown 位置不一致，且 system、历史与其他来源没有保留正文。

## 后果

- 旧事件没有 `locators`，仍按规则与来源并集显示，进入请求记录时不高亮。
- 部分工具结果 ID 可能被 Generation Chain 重映射，此时命中退化为 Run 级定位。
- 迁移 `0028_credential_mapping_rules` 为映射增加 `rule_ids`，参考 schema 一并重新生成；已有映射得到空数组，其保护不变。
