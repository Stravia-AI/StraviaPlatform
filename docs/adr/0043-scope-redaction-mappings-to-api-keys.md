# 可逆脱敏映射以 API Key 为隔离边界

> **局部被取代。** [ADR-0090](0090-gate-credential-protection-by-rule-and-strength-and-expire-mappings.md) 取代下述局部约定：本文「占位符复用」中的出站复用须尚未过期，且归因为空或至少一条创建规则当前启用；禁用、停用、删除规则或检出过期不阻止旧占位符还原。「保留时间」中已发布映射按首次发布加 N 回收，改为按 `last_detected_at + N + G`（G 为一小时）滑动到期，仅真实规则检出可续期，到期且无引用才回收。迁移 0053 取代 0045 的按使用续期；Turn 节点引用保护与 Principal 访问边界不变。

> [ADR-0089](0089-share-content-store-and-normalize-observation-writes.md) 部分取代本文「保留时间」与占位符复用中的有效期约定：映射不再有可续期的到期时间，改为被 Turn 节点引用时不回收、失去引用后按未发布窗口或首次发布时刻加统一历史保留天数回收，扫描是唯一的删除方。映射的访问边界仍只看 Principal，不因此改变。

Stravia 持久化可恢复凭据原文的可逆脱敏映射状态，使后续轮次及进程重启后仍能还原 Provider 返回的已有占位符。映射只以 Stravia API Key 对应的 Principal 为访问隔离边界；同一 API Key 下持有有效占位符时可跨对话和分支还原，不要求历史祖先关系，其他 API Key 不得还原。

此边界与现有 History Marker 一致：Marker 以 Principal 和引用查找，并受有效期与发布状态约束，不额外按对话或分支授权。曾考虑只允许继承祖先映射，但它会限制同一 API Key 下的跨对话复用，因此不采用；共享 API Key 的调用方也共享此访问边界，不能依赖对话分支隔离秘密。

## 占位符复用

同一 API Key 下相同秘密在映射存续期间复用同一占位符，覆盖历史、工具结果与不同对话中的重复出现；映射被回收后重新分配，不复活已删除的映射（回收前，即使已过下限窗口尚未被扫描，映射仍可复用）。不同 API Key 不共享占位符或映射。

每次请求重新分配可以降低上游跨请求关联相同秘密的能力，但会增加映射数量并改变模型上下文与缓存前缀，因此不采用。稳定复用保留值的相等关系，代价是 Provider 能从相同占位符判断秘密被重复使用，尽管看不到原文。

只在当前请求内存中保留映射可以减少额外持久化的秘密状态，但无法保证还原上游续接上下文中的旧占位符，因此不采用。持久化方案使本地存储成为秘密保护边界。

## 保留时间

可逆脱敏映射与 History Marker、原生压缩登记同属依赖，遵循同一条按引用保留的规则，不新增独立的映射保留时长，也不再保存可续期的到期时间：映射被任一 Turn 节点引用（`turn_node_redaction_mappings`，登记、复用或还原该映射的提交写入）时不回收；没有引用时，未发布的映射在 `pending_until`（一小时，不随保留天数变化）后回收，已发布的映射在首次发布时刻加管理员设置的历史保留天数 N 后回收。Generation Chain 提交不再续期映射。扫描是唯一的删除方：过了下限窗口但尚未被扫描的映射仍可读、可复用、可被新节点引用，被引用后继续保留。映射不以来源对话或分支是否存在作为额外访问或即时删除条件，访问边界仍只看 Principal。ADR-0089 的依赖保留只能在提交时从请求取得映射引用，因为 Generation Chain 可能保存原文而不是占位符，无法从载荷反推。

## 本地存储安全边界

可逆脱敏映射沿用 History Marker 现有的 SQLite/PostgreSQL 存储安全边界，不新增应用层静态加密或密钥管理。此功能保护发给模型 Provider 的命中秘密，不承诺防御本地数据库被读取；数据库、磁盘及备份由部署环境保护，现有日志与诊断脱敏控制不得因此放宽。

只加密映射不能保护 Generation Chain 等其他可能含有原文的持久化历史；覆盖这些记录的静态加密及密钥恢复、轮换属于独立的存储安全改造，本功能不纳入。
