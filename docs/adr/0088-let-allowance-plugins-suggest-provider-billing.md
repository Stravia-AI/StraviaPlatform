# 由额度插件建议 Provider 成本方式，管理员确认后才写入

供应商插件读取额度时本来就确认了账户的套餐，因此 `AllowanceResponse` 增加可选的 `billing`：计费方式（`usage` 或 `subscription`）、订阅周期（`month` 或 `year`）和一个周期的官方标价（十进制金额与 ISO 4217 币种）。套餐到官方标价的对照表属于插件，随插件版本维护；Core 与 WebUI 不保存任何供应商的价格。

`billing` 缺省表示未知，不表示按量计费：插件只在明确识别出套餐时填写；免费、试用、无法识别的套餐，以及无法区分订阅与余额充值的账户都留空。`usage` 只用于确定没有订阅的纯余额账户。订阅可以只给周期而不给价格，用于按席位、企业议价、仅有非美元标价或价格随地区变化的套餐。

Core 只校验与规范化，不推断：`usage` 不带周期与价格，价格必须同时有周期，金额为正的十进制并规范化，币种为三位字母并转为大写。违反任一规则则整次额度读取按无效响应处理，使插件错误在测试中暴露，而不是静默丢弃。`billing` 随额度快照返回，沿用快照的缓存、过期保留与失败回退，不单独持久化。

识别结果只是建议，不自动写入 Provider 成本方式。成本方式记录只追加，任何新记录都会结束前一段订阅的摊销，一次误判就会改变历史摊销。WebUI 在 Provider 的成本页展示“检测到订阅”，由管理员选择采用后在编辑面板里确认并保存；管理员选择过“不计算”后不再提示。插件标价一律是美元。配置了自定义币种时，WebUI 按当前汇率（`1 USD = X`）换算标价并取整到 2 位小数，以自定义币种展示和带入；汇率不可用时保持美元，由 Core 负责展示换算。已有订阅按其填写币种与建议比较，避免展示币种变化造成重复提示。自定义币种没有其他币种的汇率，非美元标价无法换算，所以只带入周期并让管理员填写金额。

## Considered Options

- Core 内置“套餐 → 官方标价”表：Core 要为每个供应商的套餐命名与调价负责，与插件把供应商差异留在插件内的边界相反。
- 识别到订阅后自动追加成本方式记录：免去一次点击，但一次误判会截断真实订阅的摊销，且记录不可编辑。
- `billing` 缺省视为按量：会把所有未识别的账户标成按量，并向已有订阅的管理员建议切回按量。

## Consequences

- 插件契约新增可选字段；旧插件不返回 `billing`，行为不变。`CANONICAL_FORMAT_VERSION` 不变。
- 官方调价后需要发布插件更新；价格表上标注来源与核对日期。
- 没有 `allowance` 能力的供应商不会得到建议，仍手动设置成本方式。
