# Turn Chain 按内容寻址并共用二进制存储编码

不可变 Turn 节点常在不同窗口和分支重复相同的历史内容。单独压缩每个节点只能缩小副本，不能避免重复存储、编码或读取；按 Principal 内的语义单元去重，再压缩唯一内容。即使字节相同也不跨 Principal 共享，以免泄露其他租户是否持有某段内容，也不把各租户的清理绑在一起。

节点结构、外置内容和回收状态相互分离，公开节点身份与内部定位键分离。这是存储切换，不改变 Canonical Item 语义、父边、前缀匹配或物化结果；普通思考和工具正文不依赖 Debug 保存。没有按大小决定是否外置的第二条路径：选定槽位内短值和空值也参与去重，缺省与 null 继续由节点结构表达。未知扩展不拆成逐标量记录，否则恢复成本高且难以界定语义。

## 取舍与后果

- 选用 SQLite 与 PostgreSQL 共用、可独立演进的应用层编码，不依赖后端各自的压缩阈值。只在压缩确实缩小实际正文时才压缩；编码等级不是格式版本，调参不迫使重写已存帧。恢复时验证格式和完整性，不能把损坏引用当作缺省。
- 本地数字键可作定位和反查，不能作并发提交水位：分配顺序不等于提交顺序，按最大 ID 增量消费会漏掉迟提交的较小 ID。
- 用可续跑的升级转换替代长期双格式热读；普通运行不在新旧格式间回退。请求内复用物化内容应受预算限制，不把它变成持久副本或新的历史事实源。

后来三方共用内容存储，仍保留上述分离与隔离原则。现行内容身份、编码格式、物化预算与回收协议见[数据布局与性能](../design/data-layout-performance.md)。
