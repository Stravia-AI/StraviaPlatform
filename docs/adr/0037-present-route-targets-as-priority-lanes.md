# 用优先级泳道与模型组聚合池编辑 Route Target，而不是 failover 图

管理面上的节点画布容易被做成带边的流程图，或把自由坐标存进 Route。选路并没有 Target→Target 的边：已启用 Target 按 Target Priority 分组，组内走 Route Scheduling Strategy，可重试失败才落到更低组（ADR-0034）。布局坐标也不是领域状态。

因此编辑器采用单列纵向的分层泳道 + 下方已禁用停用区（ADR-0035）。每一层是一个已启用优先级组，上高下低；层内再按精确上游模型 ID（`model`）聚合为「模型组（Model Group）」容器，将同模型的多个供应商账号以紧凑筹码池展示，同层并排只表示同优先级组，不是尝试顺序或 Weight。画布、抽屉与提示都不展示 Priority 整数；跨层移动支持整层互换、整层并入上层、整组拖拽/微调，以及单账号拖拽/微调，并在层间碰撞时通过最小局部顺移打开空位而不改变其他层的相对顺序。层内排列顺序不入库。

为降低多账号池（如同一模型 8–12 个供应商账号）的配置维护成本，持久化层在 `model_backends` 上仅增加薄归属标记 `config_mode`（`shared` | `custom`），其余执行配置（首 Token 超时、重试预算、冷却时间与 7 档思考等级映射）仍物化在各目标行中，保持推理选路热路径零改动：

- `shared` 成员共享同层同模型组的完整执行配置，由后端在保存期校验一致性并支持组级原子重新生成/重置思考映射；
- `custom` 成员支持单账号独立覆盖，修改组配置时默认受保护，仅在显式勾选覆盖时恢复为 `shared`。

完整运行时选路契约见[架构设计](../design/architecture.md)。

## Considered options

- 自由节点图加 failover 边：要新持久化边和坐标，并改写 ADR-0034 的选路。
- 看起来像图画、保存再投影回 priority：打开会重排，用户摆的位置是假的。
- 独立 `route_target_groups` 配置表 + 运行时 JOIN：会把管理态配置复用耦合进推理读取链路并增加跨库约束复杂度，不如薄标记 + 保存期物化简洁可靠。
- 扁平大卡片堆叠（不按模型聚合）：多账号池下首屏可见层数过少，难以对比跨层优先级并逐个维护相同配置。
