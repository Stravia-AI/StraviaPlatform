# 所有模型 Vendor 统一使用 Wasm 插件

Stravia 将所有模型 Vendor 统一为 Wasm 插件，随程序交付恰好五个自包含 Component：一个 `base` 回退 Vendor，以及 Codex、Grok、Command Code、Devin 四个专属 Vendor。`base` 是单一 Vendor 身份，通过 Provider Profile 覆盖四个专属接入之外的全部现有供应商；拆分不能削减既有 OAuth、云认证与协议、模型发现、额度、配置选项、推理、搜索、媒体或其他供应商能力。专属身份对匹配供应商的全部连接、channel 和操作进行整体接管，缺包、缺能力、缺 channel 或运行失败都必须明确失败，不得隐式回退到 `base`。

预置与本地安装只区别分发来源及更新管理，不区别能力契约或执行通道。五个预置包直接随程序交付，在插件管理页面展示并支持本地包替换，不要求用户首次使用前逐个安装；当前仍只支持预置产物和管理员导入的本地文件，不引入插件市场、远程 URL 获取或安装时下载依赖。内置版本随宿主更新、本地替换后退出自动管理、恢复内置、兼容在途任务与不兼容更新的取消及数据保护规则保持不变。

不长期保留“内置原生、外部 Wasm”的双通道：双通道可以减少初期迁移，但容易使复杂认证、自定义协议与管理能力仅在内置实现可用，并持续产生行为差异。统一机制要求完整迁移现有供应商和特殊认证、流式语义及管理能力，而不是只迁移标准推理协议或少数样本。宿主继续拥有通用网络、存储、授权、调度、重试、Target failover 和客户端协议处理；该决定不将整个网关移入 Wasm，也不把平台策略交给供应商。

插件字节不存入 SQL。验证后的不可变 Component 按内容摘要保存为实例 `<data_dir>/plugins/artifacts/<sha256>.wasm`，数据库仅保存摘要、来源、版本、revision、epoch 等元数据以及业务和插件私有状态；必须先写入并同步产物，再提交使其生效的数据库元数据，准备失败不能替换旧安装。持久化记录不得保存任意外部文件路径。

因此完整备份与恢复必须同时覆盖数据库和 `<data_dir>/plugins/artifacts/`。SQLite 部署不能只复制数据库文件，PostgreSQL 部署也不能只备份远程数据库；缺少任一侧都不是可恢复的插件实例备份。
