# 区分错误的请求与失败的请求，并按上游尝试统计上游错误

此前只有一种错误口径：客户端视角最终失败，且包含准入前拒绝；上游尝试的错误既无聚合也无列表，供应商表的“错误”是按 (run, provider) 归属的客户端口径，被重试或切换吸收的上游错误完全不可见。现在把错误拆成两个独立事实：客户端视角的终局错误，与上游尝试收到的错误；两者各有列表、各有可用率，不互相推导。

## 决定

- **客户端错误分两类。** 「错误的请求」包括准入前拒绝，以及尚未发送任何上游请求时的平台校验拒绝：模型不存在、模型访问禁止、请求 Hook 拒绝和参数校验失败。Target 尝试记录在本地准备阶段就可能建立，不能用它代替真实发送事实；宿主发送准入通过后标记本次 Run 已触发上游。平台来源的 400/422 与缺少 HTTP 状态的稳定请求校验错误码均可表达本地拒绝；真实上游返回的 4xx、先前已发送过上游后再发生的本地拒绝，以及无可用 Target、额度暂停等服务失败仍属于「失败的请求」。错误的请求保留诊断记录，但不进客户端可用率的分子或分母。
- **客户端可用率** = 1 − 失败的请求 ÷ 已终结请求。已终结请求是已完成（含向客户端交接工具调用后等待续接）或最终失败、非客户端取消、且不是错误的请求的请求；取消、断线与进行中不入分母。
- **上游错误按 Target 尝试统计**，包括 capability 尝试：来源为上游的终态失败（HTTP 非 2xx、连接或传输失败、首 token 超时、200 之后的流错误、凭据被拒）。上游可用率 = 1 − 上游错误 ÷（已完成尝试 + 上游错误）。本地准备失败、未发送、取消与观察丢失不进分子分母；上游判定为请求本身无效的 4xx 仍计为上游错误，由列表的状态码供人判断。
- **供应商表整表改为上游口径**：上游请求数、上游错误数、上游错误率。
- **统计持久化新增**已终结请求数、失败的请求数、上游请求数、上游错误数，分别记在全局与供应商 scope；上游尝试沿用所属 Model Turn 的起点分桶。迁移前的旧桶不近似，显示为空缺，只为保留期内的明细回填。
- **管理 API 破坏性切换**：统计接口移除 `error_count` 并新增上述计数，供应商统计字段改名；`/observations/failed-requests` 改名为 `/observations/client-errors` 并带类型字段；新增 `/observations/upstream-errors`。不保留旧路径别名。

## 考虑过的备选

- 以“是否形成 Inference Run”划分错误的请求：零新增分类，但模型名写错、无权使用模型会拉低可用率。
- 分母含取消、断线与进行中：编码 agent 取消频繁，取消会被当作成功而虚高可用率。
- 上游可用率排除“请求级”上游拒绝：该分类目前不持久化，需要额外字段与判定，不值得。
- 按尝试自身起点分桶：每个尝试要拆成两个 source 行，实现复杂，而桶最小 15 分钟。
- 用旧 `error_count` 近似迁移前历史：旧口径把拒绝算成错误，数值不可信。

## 影响

- 统计桶永久保留；迁移前的明细一旦过期，历史无法重算，因此旧窗口只能显示空缺。
- 上游错误的明细与列表随观察保留期（默认 7 天）过期，可用率曲线不过期。
- 上游发送前参数校验拒绝的扩展分类只作用于升级后收口的请求，不重算既有运行分类与长期统计桶。
- 供应商表的“请求数”变为上游尝试数，会因重试而上升，与全局请求数不再同单位。
