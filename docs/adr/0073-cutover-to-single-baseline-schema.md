# 冻结基线 Schema，并从基线保留数据增量升级

SQLite 与 PostgreSQL 以冻结的 `0001_baseline.sql` 为支持的数据兼容性起点：基线之前的迁移链不再支持，但从基线开始，已有部署用新增迁移原地升级，不重新初始化，不改已发布 migration 或其 checksum。这样只维护一个演进方向，不必为旧布局长期保留读取兼容层，也不会让已采用基线的部署为每次 schema 变动重建数据库。

## 兼容性边界

- 仅对真正的空库初始化。已有库必须有连续、成功、可验证的迁移前缀；未知版本、缺口、失败记录或没有迁移历史的非空库明确拒绝。唯一允许的 checksum 差异是完全相同 SQL 的纯 LF 与纯 CRLF 表示；在 runner 中消解该差异，不重写历史记录，也不放行其他字节变化。
- 升级前备份完整数据根及外部数据库。新约束不满足时显式失败，不静默删除或修复业务数据；回退靠恢复同一份升级前备份，而不是用旧二进制读新格式。离线复制只搬迁与优化受支持的数据根，不转换源 schema；目标启动时继续迁移。
- 保守检查用于表重建、数据转换及未审核的 SQLite 迁移；只有明确审核且不需关外键的迁移才跳过与变更无关的全库扫描，仍由外键约束拒绝违规写入。启动验证不是全库完好性证明；已经成功提交的数据转换不在每次启动时重跑。
- 数据库 schema、内部存储格式和领域载荷版本独立演进。类型收紧而有效载荷不变时无需重写历史；真正改变持久化表示，必须提供明确的版本与迁移路径。

当前检查策略、升级钩子和回退边界见[数据布局与性能](../design/data-layout-performance.md)。
