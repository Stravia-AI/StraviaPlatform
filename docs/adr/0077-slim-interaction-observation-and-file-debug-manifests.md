# 精简 Interaction Observation 事件并把 Debug manifest 移出数据库

普通 Observation 是可以出现缺口的诊断记录，不是推理、历史恢复或结算账本。持久事件保留独有事实和必要的顺序，不为只起唤醒作用的信号重复写入状态。合并生命周期事件时仍保留失败、中断和迟到的已知交付与用量事实；更晚确认的事实不能回填到已发布的旧水位里。若再删除有业务意义的时序边界，回放与管理端将无法区分真实发生顺序。

普通诊断按 Canonical Item 收口保存可读思考和已交付内容，不把签名或密文放进普通快照。只存 Debug Wire 会让常规详情依赖抓包开关和分段解码；逐 delta 持久化则为尚未结束的内容放大写入。易失预览可以更新、合并或丢失，但不推进持久游标；无法证明增量完整时从权威快照重建，而不是假装补齐。诊断工具结果仅在有证据时消除回放副本，不因工具 ID 相同吞掉独立分支的收据。

## 为什么 Debug manifest 属于文件

Debug Wire 与其 manifest 都归捕获它们的 Gateway 实例所有。共享数据库里的镜像只增加周期写入，不能让另一实例取得实际文件。采用同目录原子替换的 manifest 与可重建的本地索引；正常收口先保存 manifest 终态再通知 Run 结束，避免事件先到而详情仍显示旧状态。写入失败保留诊断缺口，不伪称已经持久化，也不让某一 Trace 的问题影响不相关的推理。文件清理遵循实际归属与保留期，不把数据库当作第二份 Debug 状态。
