# 以有界同步等待交付可查询的工具执行

> **局部被取代。** [ADR-0091](0091-read-paths-with-colon-selectors-and-plain-fields.md) 取代下述局部约定：StraviaRead 的 `?wait=<非负整数秒>` 查询参数改为顶层 `wait` 字段；执行引用仍作为 `path`，缺省仍立即返回。同步等待窗口、后台交接、取消与查询语义不变。

`generate` 与 `StraviaRead` 的所有对外入口统一采用工具声明的同步等待窗口，未声明时默认 60 秒；快速完成保持原工具结果，窗口耗尽后以 `stravia://tool-executions/<id>` 交付仍在运行的一次平台工具执行。StraviaRead 使用单 `path` 输入查询该引用，`?wait=<非负整数秒>` 控制本次最长等待，缺省立即返回；查询只观察原执行，不创建后台查询任务或重放原调用，内部 Agent 基础工具暂不改变。

执行状态与结果持久化，引用按 Principal 隔离且不授予权限；后台交接持久化提交前调用方断开则取消本地执行，提交后不因原请求断开或引用未送达而取消，进程重启中断未完成执行且不自动重放。查询原执行失败或中断时，以成功的查询结果返回明确状态与错误，不把任务失败混为查询失败。

上述取消分界也适用于 Inference Run 中采用本契约的 `generate` 与外部 `StraviaRead`：即使其 History Marker 已发布，在后台交接提交前原请求断开仍取消本地执行。Marker 发布不是执行归属交接；后续请求只取消自己的查询或恢复等待，不取消共享执行。取消仲裁实际获胜时，工具输出为明确的取消结果，Marker 持久化该次调用与取消结果，恢复时使用该结果；不因原请求的 Hook 无法继续而另换成交付处理错误，不为此保活或重启旧 Hook。已完成的终态不因随后断线改成取消。

History Marker 固定恢复本次实际交付的工具结果，包括工具返回的执行引用，不随后台执行完成替换为最终结果。ToolResult Hook 只处理所属 Inference Run 实际交付的工具结果；后台完成不保留或重启原请求的 Hook 会话，后续 StraviaRead 查询的返回值由查询所属请求的 Hook 处理。

除上述已经确定的取消结果外，原请求消失、导致 ToolResult Hook 无法完成时，Marker 收口为明确的“工具结果交付处理未完成”错误，不把未经该 Hook 处理的原始结果当作成功交付的 fallback。该错误不宣称工具未执行，也不取消已交接执行或改写其独立最终结果。系统确定的取消工具结果不是未经 Hook 处理的原始成功结果，不适用该 fallback 禁令。

## 执行 module 与 seam

采用统一工具分发入口：Platform Tool Execution module 向普通调用方提供调用与查询的 interface，工具 implementation 只承担领域工作。复用既有注册信息集中确定执行策略，不在工具实现内自包公开执行生命周期，也不按 ToolId 特判是否绕过执行门；内部 Agent 基础工具不因此自动获得公开执行引用。

History Marker 调用方使用专用 adapter，以少量不可复制的阶段句柄协调 Marker 准备、实际发送确认与结果封存，不向普通调用方暴露完整执行状态机。Client Projection 与 Delivery 保留 Marker 的持久化、交付、Sent 确认和 publish 顺序；具备所需交付事实前不得启动可能产生副作用的领域工作。ToolResult Hook 留在所属 Inference Run，adapter 封存其处理后的本次交付结果，或系统已经确定的取消结果，不让后台最终完成依赖原 Hook 会话。

claim、持久 owner、原始 deadline、执行门、后台交接仲裁、终态写入和查询通知统一藏在执行 module 后。两个事实分别持久化并拥有各自生命周期：工具实际工作的最终结果，以及 Marker 的本次交付结果（Hook 处理后的输出，或系统已经确定的取消输出）；前者不得随后台完成覆盖后者。存储 seam 继续使用 SQLite 与 PostgreSQL 两个真实 adapter，不为此新增通用任务框架或只有假想实现的 trait。

## 取舍与影响

- 选择自动转后台而非一律返回任务封装或新增主动异步开关，保留现有快速路径；同步窗口不是任务执行期限，转后台与查询都不重置原期限。
- 已交接执行及其可查询结果独立于来源请求的诊断记录；诊断到期或管理清除不取消执行、不删除结果。MCP 与 Inference Run 的公开工具执行共享这一独立生命周期；执行记录清理不等于删除独立 Artifact。
- 运行中的执行受原始 deadline 限制，结果从完成、失败或被判定中断的终态起按现有历史保留时长独立保留，查询不续期。不新增单独的保留配置，也不以来源 Observation 的剩余寿命作为结果期限。
- 升级时仍可查询的旧终态结果保留原执行引用与结果身份，从升级时刻给予一次完整的独立保留窗口；该时刻是迁移起算点，不冒充未知的实际完成时间。已经不可查询的结果不复活，已经删除的事实不补造，也不通过重放恢复。
- 上述决定取代本草案先前的来源清理关联，恢复 [ADR-0060](0060-own-interaction-observation-outside-generation-chain.md) 的诊断隔离原则：来源关联只用于诊断，不拥有执行归属，也不因普通诊断写入失败取消任务。它不级联删除 Generation Chain 或其他历史。
- **取代 ADR-0028 的局部保证：** 对本契约覆盖的工具调用，明确不再采用 [ADR-0028](0028-persist-hidden-history-behind-markers.md) 中“Marker 发布后 execution 独立于原请求”的取消分界，而以后台交接持久化提交为准。这是已确认的行为取舍，不是单纯整理执行代码；未纳入本契约的工具、后续 waiter 取消不影响共享执行、重启后不重放等规则不变。公开执行引用仍用于主动查询状态和结果，不是 History Marker 或客户端 tool-call ID。
- 取消本地执行不能保证已经接受请求的上游停止或不消耗额度；不能承诺恰好执行一次。同步等待窗口耗尽且后台交接持久化后即视为后台执行，不等待客户端确认收到引用，因此引用交付失败后执行仍可能继续。

统一分发与 Marker adapter 已落实在 `stravia-core::tool_execution`；SQLite 与 PostgreSQL 的 `0024_independent_tool_execution_retention.sql` 迁移完成执行归属与诊断保留的解耦，并保留仍可查询的旧结果身份。双库真实 HTTP 验收覆盖后台引用、来源诊断清理、重启恢复、交接前断连与 Marker 固定交付结果；存储与 Hook 回归覆盖独立保留、取消仲裁和交付处理失败。
