# Kiro CLI 3.4.0 credits

## Evidence and request

The official 3.4.0 CLI's bundled Kiro Agent Server SDK defines `GetUsageLimits` and its response shapes. The isolated synthetic ACP loopback capture described in [request alignment](kiro-cli-request-alignment.md) observed the bearer control-plane call, with no real account or public model call: `POST /`, `x-amz-target: KiroControlPlaneBearerService.GetUsageLimits`, `content-type: application/x-amz-json-1.0`, `tokentype: API_KEY`, `authorization: Bearer [synthetic]`, `amz-sdk-invocation-id`, and `amz-sdk-request: attempt=1; max=1`. Body: `{"origin":"KIRO_CLI"}`. The CLI also sends AWS SDK and client user-agent headers; Stravia does not claim its installation fingerprint. As with model discovery, the official runtime region selects the corresponding `management.{us-east-1,eu-central-1}.kiro.dev` origin. Stravia makes one host request, caps the successful response at 1 MiB, and propagates transport/upstream errors.

The authenticated Linux CLI 3.4.0 ACP run also returned HTTP 200 for `GetUsageLimits` on the US management endpoint. The login branch included `profileArn` and did not send `TokenType: API_KEY`. Its response contained `nextDateReset`, `overageConfiguration`, `subscriptionInfo`, `usageBreakdownList` and `userInfo`. The observed breakdown paired `resourceType: "CREDIT"` with `unit: "INVOCATIONS"`, including precision usage and limit values; this pair is displayed as credits. No real balance, email or account identifier is included here. This exchange did not include active trial or bonus data.

## Response mapping

The bundled Smithy schema defines `usageBreakdownList`, `subscriptionInfo.subscriptionTitle`, `userInfo.email`, `nextDateReset` and, for each breakdown, usage/limit with optional precision variants, `freeTrialInfo`, `bonuses`, `currentOverages`, `overageCap`, and the distinct monetary `overageCharges`/`currency`. Precision fields take precedence; missing values stay missing, and decimal subtraction uses exact decimal arithmetic. `AGENTIC_REQUEST` or `CREDIT` without a unit, or a breakdown explicitly marked credits, uses credits; unknown dimensions use generic units. The schema enumerates trial statuses `ACTIVE`/`EXPIRED` and bonus statuses `ACTIVE`/`EXHAUSTED`/`EXPIRED`. Only active, unexpired trial and bonus entries are shown; unknown status or a known expiry without a usable clock cannot establish an entitlement. The main allocation, trial, each bonus, and overage are separate items and are never summed. The cap's unit and its relationship to current overage are not established by this capture or schema: current overage is shown in generic units with no cap or inferred remaining, and monetary charges are not converted to credits. Trial expiry, bonus expiry, and reset timestamps are Smithy epoch seconds converted to milliseconds. Percentage-only `limits` are not converted into credits. The response's subscription title and email are used only when supplied; there is no guessed plan, price, or billing kind. Kiro's [billing documentation](https://kiro.dev/docs/billing/) and [add-on credit documentation](https://kiro.dev/docs/billing/add-on-credits/) describe the separate trial and add-on allocations; its [overage announcement](https://kiro.dev/blog/cap-prepay-overage/) distinguishes capped team overages from individual prepaid credits.

Guard keys encode the upstream `resourceType` and `dimensionType`, and for bonuses also `bonusCode`, rather than their array positions. Missing resource type or active bonus code, or duplicate identities, make the response invalid instead of silently reassigning an existing guard to a different pool. This does not assume an identity not present in the API.

## Test boundary

Unit fixtures exercise precision preference, independent trial/bonus/overage entries, epoch-second conversion, partial fields, unknown dimensions, percentage-only data and malformed envelopes. They are synthetic schema examples, not live response captures; the loopback capture establishes the request, not actual account balances or billing behavior. No real credentials or quota values are recorded here.
