# Vendor Plugin 市场与分发

市场是「供应商插件」的在线获取入口，与离线导入和程序随附版本共用 Core 安装协调器。
`vendor_id` 是唯一安装身份；同一 Vendor 不同时安装多个来源。组件运行、连接授权和网络权限见 [Vendor 插件](vendor-plugins.md)。
发布构建与签名流程另见[发布说明](../releasing.md#vendor-plugin-目录与签名)。

## Plugin Source 与信任

一个 Plugin Source 对应一个公开 GitHub 仓库。用 HTTPS 仓库地址登记，经 GitHub 元数据或 updater 解析后固定不可变的数字 `repository_id`。
`owner/repo` 可随同一仓库改名更新，旧名称被其他仓库复用不能接管来源。第三方首次经 updater 解析时须明确该信任依赖当前网络路径。

- 官方来源是 `Stravia-AI/StraviaPlatform`（仓库 ID `1350654373`），由宿主内嵌独立的 [Minisign 公钥](../../backend/crates/stravia-core/assets/stravia-plugin-catalog.pub)；只可禁用，不能删除、替换或由目录自报。
- 第三方来源先预览仓库与完整公钥指纹，再由管理员确认固定。公钥与目录来自同一路径属于 TOFU，不能抵御首次连接已被篡改；应通过独立渠道核对指纹。
- 公钥改变会阻止安装、更新及未提交的旧预览，旧密钥的后续网络响应不能解除阻止。显式重新信任展示新旧指纹、推进信任修订并使旧缓存和预览失效。
- 官方密钥轮换只随经验证的宿主更新引入。Desktop 产品更新公钥和 Release 的 `SHA256SUMS` 都不是 Plugin Catalog 信任根。
- 添加来源只固定来源身份，不安装代码，不授权连接秘密；有效签名不等于代码安全，也不证明目录最新。凭据授权见 [ADR-0068](../adr/0068-trust-vendor-plugins-with-connection-credentials.md)。

第三方来源可启用、停用或单独允许预发布（默认关闭）；官方来源的预发布策略直接跟随产品更新通道（`release` 仅正式版，`beta` 允许预发布），不在来源设置中单独覆盖。移除第三方来源不卸载组件、不删除数据，但停止跟随该源；已安装项保留来源快照，重新登记不按仓库名自动绑定。

### 来源登记与检查状态

登记地址只接受 `https://github.com/{owner}/{repo}`，允许仓库名后缀 `.git` 或尾部斜线；拒绝端口、子路径、用户信息和查询参数。
仓库身份校验、固定公钥和是否启用是独立条件；普通来源设置不能顺便换钥或换仓库。

工作台区分未检查、上次成功、异常与已失效缓存；已停用或检查失败不显示「已是最新」。预览校验失败不变更已存在的安装或来源。
来源确认绑定预览中的仓库身份、公钥及当前管理员会话，不将后续网络结果偷偷替换进去。

## 签名目录与分发包

宿主读取公开、非草稿 Release 的 v2 Plugin Catalog：`stravia-plugin-catalog.json`、同名 `.minisig` 和候选 `.pub`。
先用固定公钥验证目录原始字节，再使用元数据。目录绑定仓库 ID、Release tag 与实际资产，不接受任意下载 URL；Release tag 不替代插件 SemVer。

- 签名目录描述 Vendor 身份、版本、明确的宿主版本范围、WIT／canonical 兼容性，以及压缩和组件各自的大小与 SHA-256。展示名、作者和时间不构成认证或排序依据。
- 未知 schema、重复 JSON 键、未知字段、重复资产／版本及不安全文件名不得进入安装。同一来源同版本若出现不同 Component 摘要，标为冲突，不任选其一；相同内容可合并。
- 目录中的图标只作为图像展示，不注入 HTML。未发布目录的仓库不能靠文件名猜测身份或绕过验证；管理员可另行离线导入。

### 为什么用 `.wasm.zst`

选择 Zstd-19，而不是体积略小的 XZ-6e：解压更快，并复用 Core 已有的 `zstd` 依赖。市场只接受这种压缩资产，不协商其他格式。

1. 流式限制下载大小，拒绝非 identity 的 HTTP 内容编码，核对压缩原始字节的声明长度与 SHA-256。
2. 在受限任务中解压；只接受一个标准 frame、无字典、最大 8 MiB window，无拼接 frame、skippable frame 或尾随字节。压缩输入和解压结果均不得超过 64 MiB。
3. 再校验解压 Component 的长度与 SHA-256；执行 Wasmtime 准入，核对真实 descriptor、Vendor 版本、canonical 代际及实际 WIT 导入。宿主版本范围是独立的发布声明。

输入、输出都在处理过程中有界，不先无限下载或展开再拒绝。Release 分页、目录、签名公钥与并行安装准备同样有限；扫描达到上限时不声称遍历全历史。

### 发现和下载限额

| 输入 | 边界 |
| --- | --- |
| Release 元数据 | 每页 100 条且不超过 1 MiB，最多 10 页 |
| 单个目录 | 256 KiB，最多 100 条插件发布记录 |
| 单个公钥或签名 | 4 KiB |
| 并发安装准备 | 实例内最多两项，等待和未完成的准备可取消 |

宿主只获取选定 Release 下目录或签名列出的资产，摘要绑定精确字节，镜像重定向不能替换该身份。
可选图标仅用于浏览，图标或发布者自报身份不参与安装授权。

## updater 镜像与版本发现

镜像策略以数字仓库 ID 为准；白名单只表示分发与缓存服务范围，不代表安全背书。updater 不改写签名目录，也不执行组件。

- 纳入镜像的仓库经 updater 获取目录和资产；资产请求按当次连接分流，可由国内缓存交付或重定向 GitHub。缓存按仓库、Release／资产身份及摘要隔离，不能以同名文件跨源复用。
- 只有明确返回 `not_mirrored` 才切换直接 GitHub 获取；网络、服务错误、未知响应、完整性或签名失败均不换路径。失败可保留带过期标记的旧展示数据，但不授权安装。
- 获取复用 `update_uses_proxy` 与实例共享出站设置，不继承任何 Provider 凭据、Cookie 或 OAuth 令牌；WebUI 不直接下载或解压。

按插件 SemVer 在扫描范围选择最高兼容版本，不使用 GitHub `/latest`、tag 字符串或发布时间排序。Release 或插件版本任一是预发布，均须来源显式允许。
有更高但不兼容的版本时提示升级宿主，不能说已最新。相同排序优先级但内容不同须显式选择，SemVer build metadata 不提供优先级。

启动后及定时任务检查到期来源，也支持打开工作台时检查和手动刷新。软件检查失败不阻止插件检查；成功缓存 24 小时，单源失败不遮蔽别的来源。
同源并发刷新合并，跨实例拒绝旧检查结果覆盖新结果。自动检查只更新可用状态，不下载全部 Wasm、执行未选组件或安装更新。
已见版本摘要用于阻止替换与自动降级；首次安装仍可能看到旧但有效的目录，签名不证明新鲜性。

### 镜像服务的授权边界

updater 将固定名称的元数据与经目录授权的组件资产分开处理；组件还须确实存在于同一 Release、大小匹配。
区域与缓存由实际资产请求决定，不把目录查询时的地区长期绑定到 URL，也不把「未收录」当默认错误回退。

是否经镜像不影响最终验签、双摘要和组件准入；updater 的解析不是宿主的认证依据。
插件分发错误与软件更新保持各自状态，不把服务故障或签名失败冒充暂无插件更新。

## 统一安装生命周期

### Install Origin

安装来源取实际提交的 `builtin`、`local` 或 `marketplace`，不采信包自报的「官方」。见 [ADR-0091（插件来源）](../adr/0091-authenticate-plugin-catalogs-and-pin-install-origins.md)。
市场记录同时固定来源、仓库、指纹、发布身份与摘要，与安装 revision 同事务提交。正常市场更新只接受原来源的严格更高版本；换源、降级或重新安装须显式预览确认。
本地包字节即使与官方发布一致，也不自动获得市场来源。官方目录可与同 Vendor 的随附安装合并展示，但不自动绑定或改变更新策略。

### 预览与确认

1. 确定来源及确切版本；市场验证目录和双摘要，离线导入验证输入格式与组件准入。所有方式验证宿主契约兼容性。
2. 预览实际旧新来源、版本与受影响连接，说明凭据继承、网络权限变化、能力移除、降级、数据重置及在途任务影响。
3. 管理员确认后再提交。预览有界、会话隔离、有效期 15 分钟；来源、信任修订、组件 revision 或当前数据状态不再匹配时拒绝，不自动重做预览再提交。
4. 仅提交绑定的已验证字节，不重新从可变地址下载。安装失败保持原记录和来源；原组件若与宿主本身不兼容，仍不得继续执行。

手动确认授权新代码继承预览列明的连接凭据，不授权额外数据清除。兼容更新可移除能力，保留原绑定并显示不可用；不换账号、不改绑、不回退普通推理。
准备阶段显示真实字节进度（总量可知时）或当前步骤；取消不提交安装。

确认是一次提交，不存在「下载成功即安装」的中间生效状态。
共享数据库下，安装事务重检来源的信任和冲突状态，revision 竞争的失败者不能覆盖后提交的版本。

工作台提示来源未适配、来源身份变化、签名失败、版本冲突、不兼容、限流、网络失败、损坏、资源上限和预览过期。
管理员可对照旧新版本及其来源，不把错误显示成安装成功或无更新。

### 本地包、随附版本与恢复

- 管理员可离线选择本机 `.wasm` / `.wasm.zst`；Server 浏览器把文件上传到当前实例，Desktop 导入本机实例。压缩复用相同解码限制，检查 MIME 与实际格式；无签名目录不宣称验证发布者。
- 不接受服务器文件路径、任意远程资产 URL 或安装时下载运行依赖。市场不分发或替换 `base`；管理员仍可本地替换。
- 普通发行版只内嵌 `base`；Nix Server 的 `bundled-vendors` 内嵌同次源码构建的官方插件，首次设置完成后自动装为 `builtin`。开发构建的本地产物准备见[开发环境](architecture.md#开发环境与-patch-crate)。
- 仍为 `builtin` 的插件在启动时自动更新到更高随附版本，或同版本但新摘要；同版本同摘要不重复安装，低版本不自动覆盖。
- 本地或市场覆盖后进入手动管理，不会被随附版本覆盖。若有随附产物，可显式「恢复内置版本」，确认版本与影响后重新取得自动更新资格；显式恢复可能降级。
- 随附版本只来自当前程序字节，不走市场；不再随附的专属插件不会被自动卸载，也无法恢复一个不存在的随附版本。

### 数据兼容与任务协调

兼容升级发布新 revision 后，新调用使用新版本；已开始的调用、资源和结果收口保持原组件，不在流中途替换。
不兼容数据的手动升级／恢复需明确确认。内置来源 `base` 随宿主更新可按格式版本差异自动选择性重置并应用新网络声明；其他随附插件若需丢弃数据，保留旧安装和数据并告警。

- 只重置不兼容的供应商选项、私有状态、凭据或模型发现元数据。保留 Provider 身份、兼容配置、Route/Target、历史、用量和额度采样；受影响 Target 等待重新配置、登录或发现。
- 先停止该 Vendor 的新任务准入，取消并排空全部连接操作和待配置认证，撤销旧发布与写回；其他 Vendor 不受影响。
- 不能确认旧任务已停止并失去写回资格时，不得继续重置或报告成功。迟到认证、搜索报告和图片不能重新生效。
- 取消不保证上游已停止执行或计费；保留已确认用量，不重放中断操作。

切换后只有具备有效配置及凭据的连接可继续执行。能力移除与数据不兼容都不删原 Route 绑定，也不以其他 Vendor 代替。
安装协调与管理适配共享同一 Core 行为；没有桌面专用安装事务或独立的市场直写路径。

### 卸载与备份

除 `base` 外可卸载，包括组件缺失或加载失败的安装；卸载不依赖成功加载。先确认依赖影响，停止准入、取消并排空，再撤销旧写回、移除安装记录及运行态、使相关旧预览失效。
保留连接、凭据、模型、Route/Target 绑定、历史、用量、私有数据、恢复标记和内容寻址产物；不自动删除数据或改绑。重新安装须预览，若保留数据无法证明兼容须显式确认重置。

程序随附 Component 不另写产物文件；本地与市场安装的不可变字节在 `<data-dir>/plugins/artifacts/<sha256>.wasm`。
先校验并可靠落盘，再提交安装元数据；事务失败不发布新 revision。组件原始字节不放入 SQL，安装记录不保存任意路径。
完整备份须包含数据库和本地产物目录，SQLite 与 PostgreSQL 相同；数据库备份本身不能恢复离线导入或市场安装的代码。

### 备份恢复与管理入口

本地导入的原文件路径与文件名不是恢复契约，恢复只认可数据库指向的固定摘要与已校验组件字节。
迁移数据根时需一起迁移 `plugins/artifacts/`；仅完成远端 SQL 恢复不等于插件已可执行。

在线安装和本地导入都需已认证管理会话。来源管理与安装准备是不同操作，添加一个源不会直接让其代码取得凭据。
管理工作台可以离线显示安装记录及旧缓存，并明示来源缺失、停用或过期，不把无法确认的版本标为最新。

安装实现见 [PluginManager](../../backend/crates/stravia-core/src/plugin/manager.rs)；来源和安装元数据见 [SQLite](../database/sqlite.sql) 与 [PostgreSQL](../database/postgres.sql)。
