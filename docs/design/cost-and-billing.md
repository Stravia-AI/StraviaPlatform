# 成本与计费

**估算成本**估计实例应付给上游的金额，从不拦截请求；**计费**按 Route 定价向 API Key 记账，可用于消费上限准入。
上游价格、Provider 成本方式和 Route 计费分别配置。已确认用量与尝试终态见[交互观测](interaction-observation.md)。

## 冻结金额与币种

Core 使用 `rust_decimal::Decimal` 解析、计价和换算，不经二进制浮点。管理接口收发十进制字符串，目录价格仍可为 JSON 数字。
每笔分项先累计，再分别四舍五入（中点远离零）到美元和自定义币种的纳单位，存为 `i64`；不可表示时记未知，不截断。

- 每笔已知尝试成本、计费和订阅价总是冻结美元金额；当时已配置自定义币种时也冻结该币种金额。
- 美元填写项在美元侧取原价，自定义侧乘当前汇率；自定义币种填写项在自定义侧取原价，美元侧除当前汇率。混合币种先分别累计再对两侧取整。
- 实例只允许一种自定义币种。`symbol` 是 1–8 字符的显示符号，不是 ISO 币种代码，也不是换算依据；`usd_rate` 表示 1 USD 对应多少自定义单位，必须大于 0。
- 改符号只改显示；改汇率只影响之后冻结的金额。币种一经设置不能删除，`first_rate` 永不改写。

首次设置在事务内保存币种，并按 `first_rate` 一次性换算现有非空 API Key 上限。
不回填尝试、统计或订阅事实。由 `/api/v1/currency` 管理；通用 settings 写入不得绕过此约束。成功提交后才替换计价读取的币种快照。

历史聚合分别累计已有自定义金额和未换算美元；显示值是前者加后者按 `first_rate` 换算后的值。未配置时直接显示美元。
单笔详情先取已冻结的自定义金额，否则同样按首次汇率显示，不用当前汇率重估。换算由 Core 完成。见 [ADR-0086](../adr/0086-freeze-dual-currency-amounts-and-derive-history-from-first-rate.md)。

例如，实例首次设置的汇率为 7，历史的 1 USD 显示为 7 个自定义单位。
之后设为 8 时，新算定的 1 USD 冻结为 8 个单位；两笔合计显示 15，而不是用当前汇率把两笔统一重算为 16。
这条规则也适用于订阅历史价格和消费累计，不因符号变化改写事实。

## 价格结构与计算

Provider Model 与 Route 按 Token 计费共用 `ModelCost`，价格单位均为每百万 Token。基础价和上下文分档可分别表达输入、输出、缓存读、缓存写。
`custom_currency_fields` 标记用自定义币种填写的价格组；`tiers` 标记同时覆盖 `context_over_200k` 和全部分档。无自定义币种时不接受该标记。
`peak` 是至多一条本地定价规则：IANA 时区、ISO 星期、同日不重叠的左闭右开区间与正倍率，结束时间可为 `24:00`，不跨午夜。
目录和模型发现只可提供美元价，不能设置本地币种标记或峰谷规则。峰谷不推断法定节假日或调休。

计价读取尝试开始时间与冻结配置，使用已确认的总输入 (I)、输出 (O)、缓存读 (R) 和缓存写 (W)：

1. (I) 或 (O) 未知时结果未知。缺失的缓存细目在计价时按零，不能据此把统计中的未知变成已知零。
2. 选择严格满足总输入大于阈值的最高档；没有匹配用基础价。`context_over_200k` 按 200000 阈值参与选档。
3. 普通输入计 `max(0, I - R - W)`；输出、缓存读、缓存写各用自己的价格。正用量缺价使本笔未知；零用量不要求有价。推理 Token 已含于输出，不重复计价。
4. 尝试开始时刻在指定时区命中峰段时，全部分项乘 `multiplier`。再按填写币种分项累计、换算及取整。

计价的普通输入扣缓存读、写两项，不等于[管理面净输入](interaction-observation.md#confirmed-upstream-usage)只扣缓存读。
路由流量权重使用同一价格来源，自定义价按当前汇率折算美元；不会重算历史金额。

这里的分档依据完整输入（含缓存输入），不是计量页显示的净输入。
峰段起点包含、终点排除；按尝试开始时刻转换时区，不按查询时间、客户端时区或完成时刻计算。

### Provider Model 价格来源

人工固定字段优先；未固定字段跟随模型同步。来源价格整组的优先级：

1. 渠道自己的发现价或目录价，例如 Devin 账号协议报告的美元价。
2. 渠道整组缺价时，才查同模型厂商的官方 API 目录作按量参考；不能拿转售商或同品牌另一 scope 的价格补齐。
3. 无合格来源则保持未知。渠道部分报价（含零）已算有价，不和官方价拼成一组。

官方 scope 依据 Canonical 厂商身份，混合渠道逐模型解析。优先用显式 `canonical_id` 或已知 Canonical 来源身份，随后才用精确 ID、有限格式归一或唯一名称匹配。
归一保留版本、日期、preview 与其他 variant，不跨版本猜价；Claude 末尾 `thinking` 可作为价格别名。
多个官方条目共用同一 Canonical ID 时优先精确型号 ID，再按忽略大小写的最小编辑距离；并列仍不猜。

价格富化不改变模型集合、selector、能力或其他规格。可选官方目录不可用时记录失败并保留上次有效价格，不损害已成功的账号发现；成功刷新后明确无价则未固定参考价恢复未知。

手动添加预填和创建共用发现价富化；价格参考不会把目录成员变成已授权模型。
订阅模式使用官方价计算对比值，不将官方公开 API 报价解释成订阅实际支出。

### 逐字段固定与恢复同步

同步模型保存最新来源快照，即使某些字段已固定。提交的修改字段立即固定，即使值恰与来源相同；未修改字段继续跟随同步。
价格币种标记随对应字段固定或恢复，`cost.peak` 是纯本地规则，不参加固定。无同步来源的手动规格只在创建时可复制模板。

恢复同步从最新来源快照写回所选字段并取消固定；来源缺字段则恢复为未登记，不发起上游请求。
若有效 `reasoning_efforts` 改变，同事务重算关联 Target 的 Generated Mapping，不覆盖手改映射。
见 [ADR-0084](../adr/0084-pin-provider-model-fields-individually.md) 与[思考等级映射](vendor-plugins.md#自定义协议与思考等级映射)。

## 估算成本

### Provider 成本方式

| 方式 | 尝试估价 | 窗口内实际成本 |
| --- | --- | --- |
| `none` | 不计算，也不增加未知数 | 不产生金额 |
| `usage`（默认） | 用 Provider Model 和已确认用量计价 | 已知按量尝试成本之和，另保留未知计数 |
| `subscription` | 保留等价按量估价 | 只计订阅摊销，不加等价按量估价 |

计划只追加，从提交时刻生效，不回溯或修改旧记录。下一条计划（含 `none`）结束此前的订阅段。
删除订阅 Provider 时同事务记录终点，保留已发生的历史；复制 Provider 从默认按量开始，不重复计算原订阅。

Allowance 插件可在额度快照里提供 `billing` 建议；不会自动更改成本方式。
管理员可忽略或采用，采用必须进入可编辑表单并明确保存，仍走同一计划追加接口。
插件金额是美元，可按现行汇率预填自定义币种；无明确价格时只预填已知周期。显式选 `none` 后不再提示。
见 [ADR-0088（额度计费建议）](../adr/0088-let-allowance-plugins-suggest-provider-billing.md)。

订阅计划必须明确月／年周期、非负价格和填写币种。`none` 与 `usage` 不带订阅参数。
独立订阅生效记录的价格也遵循双金额冻结；查询时用已冻结的金额做摊销，不用后来汇率改账。

### 归属与记录

启用成本追踪时，重试、故障切换、隐藏轮次与平台内部调用都按各自尝试计价，不要求最终客户端成功。
尝试开始时固定成本方式；结束时用该尝试的确认用量一次算定。缺用量、缺价、无 Provider Model 或金额溢出均可能使成本未知。
仍运行、未记录成本方式的历史尝试及 `none` 不计入未知；崩溃恢复中断的受追踪尝试没有金额，计为未知。

金额随尝试结束事实写入 Observation，在同一事务内累计长期用量桶与 API Key 消费。
没有 Observation 作用域的调用不产生金额；代理、Agent 循环与归属 API Key 的 MCP 工具调用均使用该作用域。
队列过载或事实写入失败可能丢失金额，消费上限不是完整财务账本。见 [ADR-0085](../adr/0085-record-cost-and-billing-with-interaction-observation.md)。

已知估价为零与没算、未知分别表示。只要有已确认的非零订阅摊销，就不能因所有尝试均未知而把窗口整体画成未知。
查阅已发生金额使用与尝试详情相同的历史币种规则；WebUI 只格式化，不再做一次换算。

### 订阅摊销与统计范围

按查询窗口与订阅生效段的重叠时长线性摊销：`重叠时长 / 周期长度 × 冻结订阅价`。月按 365/12 天、年按 365 天；仍在生效的段止于查询时刻。
相邻窗口可相加，不依赖真实扣费日或续费锚点。全局实际成本为全部按量尝试金额加上所有历史订阅段的窗口内摊销。

- 订阅价值比较同窗口摊销与订阅基准尝试的等价按量成本。价值倍数用展示币种相除，保留四位小数；零分母或不可表示时不返回。
- 有未知等价成本时倍数只是下界。非零摊销仍是已知金额，但不增加已知尝试计数；未知尝试不能显示成已知零成本。
- Provider 筛选纳入相应 Provider 的订阅计划；Route 与 API Key 无法分配订阅摊销，可查看归属各自尝试的成本或计费。API Key 筛选的实际成本不含订阅。

## Route 计费与 API Key 消费上限

### 计费口径

| 模式 | 收费依据 |
| --- | --- |
| 不计费（默认） | 无记账 |
| 按次 | 每个成功 Model Turn 收固定非负金额 |
| 按 Token | 按成功尝试的确认用量与 Route 价格计费，峰谷取该尝试开始时间 |

失败、取消和中断的尝试不收费；Model Turn 至多有一个成功尝试。按 Token 缺必要用量或价格记未知，不计金额但计入未知次数。
隐藏轮次及平台内部调用同样计费；调用其他 Route 时按被调用 Route 定价，仍归根 API Key。没有 API Key 的 Principal 不计费。
Provider 选择 `none` 不关闭 Route 计费；计费配置修改仅影响之后的调用。

按次的计价单位是成功 Model Turn，不是 HTTP 请求，也不是 Interaction。
计费与估算成本允许各自未知：上游报价缺失不会阻止按次计费，`none` 成本也不等于计费免费。

### Spend Limit

上限可空（不限），配置值必须大于零，单位是当前展示币种。
在代理根请求的 Principal 准入及 MCP `tools/call` 的 RPM 准入之前读取已消费；无累计行视为零，读取失败不放行。

- 已消费大于或等于上限时返回 HTTP 429，稳定码 `STRAVIA_SPEND_LIMIT`，无 `Retry-After`；各客户端协议使用对应额度耗尽形态。
- 此拒绝记录为准入拒绝，不消耗 RPM 名额，不修改 Key 的启用状态；调高上限或清零后下次准入重新判断。
- 仅根请求检查。已准入的隐藏轮、工具调用与切换继续运行，异步累计也有延迟，因此允许超出上限。

429 不改变 Provider 额度守护或凭据健康，只说明当前 Key 不满足消费准入。
只有消费累计达到配置值才拒绝新请求，不预先预留或预测本次请求将花多少钱。

### 清零与耐久性

`POST /api/v1/api-keys/{id}/spend/reset` 只原子清零该 Key 的消费累计并记录时间，不删除历史尝试、计费或 Stats Usage。
清零前开始、清零后入账的调用计入新余额；与在途调用不做同步。可用余额为 `max(0, spend_limit - spent)`，不限时不显示余额。
已删除 Key 的迟到金额不重建该 Key 的消费行。删除诊断详情不撤销已计金额。

存储结构见 [SQLite](../database/sqlite.sql) 与 [PostgreSQL](../database/postgres.sql)。
