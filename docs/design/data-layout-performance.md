# 数据布局与存储性能

本页说明数据库与文件的职责、派生缓存、历史物化、引用回收和升级约束。执行入口见[系统架构](architecture.md)；SQL 约束、列及索引以生成的 [SQLite](../database/sqlite.sql) / [PostgreSQL](../database/postgres.sql) 为准，不用参考 SQL 初始化实例。

## 持久化后端与备份

| 后端 | 使用方式 | 权威数据 |
| --- | --- | --- |
| SQLite | Desktop 与本地 Server | 数据根 `db/gateway.db`；运行中还须考虑 WAL |
| PostgreSQL | Server 外部数据库 | 同一业务语义和保留约束；部署方管理数据库的备份与耐久性 |

两者使用独立 adapter，经 `stravia-sql` 统一池、连接与事务。并发实现不同，但授权、完整性、原子提交和可恢复性不因后端而改变。
Server 的数据库连接只归应用可写的 `server.toml`；默认在所选数据根，`--config` 可指定其他路径。缺少存储配置进入受控设置，不以连接错误、坏配置或不兼容 schema 回退 SQLite。设置及就绪见[管理认证与启动](admin-auth-bootstrap.md)。

`DataPaths` 统一解析本地存储：

- `db/`：SQLite 数据；切换到 PostgreSQL 不改变本地数据根的职责。
- `plugins/artifacts/`：已安装的外部 Wasm 字节；SQL 保存安装身份和私有状态，不保存组件字节。内嵌插件跟随程序。
- `artifacts/`：实例本地 Artifact；用外部对象存储时亦须保全对应对象与 SQL 引用。
- `diagnostics/observation-debug/`：本地 Wire Debug 文件；导出与访问边界见[交互观察](interaction-observation.md)。
- `cache/`：可重建的目录与编译产物，不是历史或安装事实源。

备份或搬迁必须取得**一致的数据库、配置和本地数据根**，包含安装插件、Artifact、诊断文件及相关外部存储。
只有 PostgreSQL dump 不能恢复整个实例；运行中复制 SQLite 主库文件不是可靠备份。
停机升级前保留同一时点的配套备份，并预留新旧格式、事务日志及暂存文件并存所需的空间。

## 统一派生缓存与 Server 配置

[`RuntimeCache`](../../backend/crates/stravia-core/src/runtime_cache.rs) 只保存可丢弃的派生数据。
SQLite / Desktop 使用进程本地 TinyUFO；PostgreSQL 启动时必须能连接 Redis。不支持用内存缓存或另一个数据库代替 PostgreSQL 的 Redis 启动配置。

```toml
[cache]
capacity_mb = 16
redis_url = "redis://127.0.0.1:6379/0"
```

`cache.capacity_mb` 是共享逻辑预算，默认 16 MiB；SQLite 不读取 Redis URL。首次设置保存数据库连接时保留已有 `[cache]`。
预算不等于进程 RSS、Redis `maxmemory` 或磁盘配额：对象仍可被活跃调用方持有，目录与容器也占实际空间。

| 缓存内容 | 约束 |
| --- | --- |
| Generation 精确物化及引用目录 | 共享预算；历史权威仍是数据库 |
| Target 定价、Cache Affinity、Provider Allowance | 各自有生效期；丢失只影响派生读与选路偏好，不创建执行事实 |
| 凭据映射快照与存在性 | 按 Principal 隔离；有效期与失效见[凭据保护](credential-protection.md) |

不同类别有固定优先级和保护份额；未用份额可借，受保护空间不会因别类扩大借用被任意挤出。
入缓存不需要序列化整条历史做估重；超预算条目、未命中或过期仍正常读权威存储。
配置、授权、RPM、锁、连接、执行进度及历史保留不依赖派生缓存。

PostgreSQL 所需 Redis 至少 6.2，推荐按实例隔离配置 ACL、TLS 与 `noeviction`，为容器、索引和连接预留实际空间。
缓存可能含请求上下文和凭据明文，不能暴露到非受信网络，也不能用作备份。每个 Gateway 以随机 namespace 隔离，正常关闭只清自己，异常退出由 TTL 回收；不跨进程复用、不支持 Redis Cluster。
启动缺失、无效或连接失败时明确失败；运行中读失败视为 miss，写失败可丢弃，不伪造数据库结果或改写已保存历史。

### 缓存准入与隔离

本地 TinyUFO 命中可克隆不可变 `Arc` 句柄，不需要序列化整段历史；Redis 边界仍需要编码与解码。
缓存估重包含身份和索引、唯一 item 分配、完整请求控制及深层 metadata；不将序列化字节数等同于容器占用。访问借用正文，不构造第二棵 JSON 树。

过期优先回收，其次从超额占用的低优先级类别腾挪空间。整条对象不可拆，准入无法在总额度内完成时不缓存；仍有效的同键旧值可保留。
本地缓存使用统一的逻辑记账与 TinyUFO 准入，Redis 在实例 namespace 内用 Lua 原子更新预算、过期与类内淘汰。策略只影响缓存命中，不改变 SQL 可见性。
配置变更的失效代次不允许在途旧读取回填过期值。Redis 不承担配置广播、进程锁或持久的跨实例协调。

### Wasmtime 编译产物

`<data-dir>/cache/wasmtime-images` 是独立磁盘缓存，不纳入 `RuntimeCache`。
从已验证 Wasm 生成可文件映射的不可变镜像，键包含源字节 SHA-256 与 Engine 兼容身份；装载前校验长度、摘要与路径可信性。
目录锁串行化校验、编译和清理；临时文件可靠落盘后原子发布，不就地改写已映射镜像。

缓存目录须由运行账号控制，不导入不受信的原生镜像。缓存不可用可从原始 Wasm 编译到内存，但不会绕过插件本身的校验。
镜像软上限为 512 MiB 和 65,536 项，清理不是内存或磁盘硬限。
具备持久编译缓存时，空闲 60 分钟的已装载插件可释放映射，再用时校验并恢复；并发恢复合并，descriptor 查询不装载代码。
`cache/plugin-admissions` 的准入记录可跳过重复启动装载，但首次执行仍验证组件和 descriptor，不把缓存作为信任锚。

## 共享正文存储与引用回收

[`content_store`](../../backend/crates/stravia-core/src/content_store/) 是 Generation Chain、History Marker 和 Interaction Observation 共用的正文存储。
正文身份是 Principal scope 内 `SHA256("stravia.content.v1\0" + format 字节 + 原文)` 的完整摘要；文本用原始 UTF-8，JSON 用紧凑编码，不把 JSON 数字归一为浮点值。
相同正文和格式在同一 scope 共用，不跨 Principal 去重，也不共享不同来源的外壳、签名或密文元数据。定义见 [ADR-0089](../adr/0089-share-content-store-and-normalize-observation-writes.md)。

### 不可变描述与二进制编码

| 保存对象 | 约束 |
| --- | --- |
| 不可变 descriptor | 保留领域结构与 JSON Pointer / ordinal 槽位，可组合字面前后缀 |
| 共享 body | 独立的文本或 JSON 正文，不持有保留期或 owner 业务语义 |
| 内容引用 | owner 的 ordinal → 内容数值 ID，是解析槽位的唯一权威 |
| 回收状态 | 与不可变内容分离，候选和 `deleting` 状态不代表内容不存在或可继续发布 |

外置以语义单元为准，没有正文大小阈值；已选槽位中的空值容器和空串仍保持准确，缺省与 `null` 由结构表示。
同一正文的多次出现保留原位置；未知扩展不拆成逐字段值。恢复验证 scope、槽位完整性、格式和带域摘要，拒绝损坏或跨 scope 的引用。

[二进制 codec](../../backend/crates/stravia-core/src/storage_codec.rs) 用于 descriptor、正文及需编码的小属性。
至少 128 B 的输入可尝试 zstd，默认压缩级别 **1**，只有实际更小时才存压缩帧；短值与未缩小的值保留原始字节。
帧格式、领域载荷版本和数据库 migration 独立演进；解码检验边界和长度，不因压缩参数调整重写历史。见 [ADR-0076](../adr/0076-deduplicate-turn-chain-items-and-share-binary-storage-codec.md)。

写入先在写锁外准备可确定的内容抽取、摘要与压缩；存在性查询只减少工作，事务内必须重新确认。
节点、payload、引用及派生索引在同一事务提交。数字内部 ID 仅定位行，不能当成并发事务的提交水位。

### 编码与恢复工作集

固定 14 B trailer 提供格式版本、原始长度、压缩标识和当前保留为零的字典标识。读取长度提示可预先限制批次，不可据此认定帧合法。
原始载荷可借用已校验缓冲；压缩载荷必须验证单帧及长度，再解压并校验正文摘要。缺失外置正文不当作空载荷。

文本槽可直接存 UTF-8；跨协议投影仍需精确恢复标记前后的字面量。拆分后不能逐字节还原时，以原串作为正文单元，不凭片段相似共享错误的内容。
同批先去重，再读取请求局部工作区没有的数值引用；普通祖先读取按最多 256 个 ID 分批。复用的是已校验的正文，不是按历史语义伪造的等价正文。

### Generation Chain 物化与提交

Generation Chain 是同 Principal 的不可变、有分支 canonical 历史。节点保存本轮输入 delta、完成输出与解析后的请求配置增量；压缩等显式替换边界使用 Replace，不周期复制整个窗口。见 [ADR-0022](../adr/0022-materialize-generation-chains-from-deltas.md)。

- **写入**：先登记待提交屏障；实际完整交付后持久化成功或 incomplete 节点及其引用，失败和取消不保存。匹配的同实例续接等待关联屏障，不把内存准备当作已提交历史；无关分支不等待。
- **读取**：按父边顺序恢复 delta，校验同 scope、kind、完整性和位置；先去重数值内容 ID，再有界加载缺失正文。冷读不重跑 Hook，不把客户端投影中的指令补进执行窗口，也不跨 Replace 拼回被删历史。
- **发现**：前缀索引是可重建筛选信息，指纹只能否决候选，不能代替 canonical 完整比较。普通发现只收窄同 Principal 分支；显式 Responses 续接见[响应链](open-responses.md#response-chain-与-store)。
- **物化缓存**：共享不可变 item，改写时才产生可变副本；按 ingress 惰性缓存引用目录，与物化结果共享预算。头节点的 `created_at + N` 限制缓存与证明复用，不是 SQL 读取条件。
- **请求内复用**：候选搜索可用单请求 16 MiB 逻辑工作区暂存已核验祖先与正文；预算不足则继续读事实源。过期证明不能截断实际历史，不缓存半链或错误，不跨请求或隐藏轮次保留工作区。

Observation 可引用同一正文，但清理诊断不删除仍被 Generation Chain 或 Marker 使用的内容；其写入和读取契约见[交互观察](interaction-observation.md)。

### 保留与有界回收

`log_retention_days`（默认 7，最小 1）是统一的保留天数 N，不是跨域共有的到期列。保存设置触发扫描而不重写历史。

| 对象 | 可回收条件 |
| --- | --- |
| Turn 节点 | 超过 `created_at + N`，且无子节点及原生压缩来源引用 |
| History Marker / 原生压缩登记 | 无引用；未发布或未确认按一小时 pending 窗口，已发布或确认按首次时刻加 N |
| 可逆脱敏映射 | 仍受历史引用保护；续期只按 `last_detected_at`，出站资格与回收见[凭据保护](credential-protection.md#检出时钟与回收) |
| Observation / Debug | 由所属诊断对象及活动状态裁决，见[交互观察](interaction-observation.md) |
| 共享正文 | 无任何 owner 引用；不单独计时 |

祖先随子节点存活，不按每次续接为整条链续期，也不维护需要每次写父行的全局引用计数。
已到期、尚未回收且未标记 `deleting` 的 Turn 节点仍可读、续接和被引用；该规则不放宽凭据映射的替换资格。

维护每小时运行，复用持久水位按期限增量扫描；删除最后一条引用的事务登记候选，扫描也登记期限内从未引用的候选。
候选不是删除许可：领取后在锁内重检期限和反向引用。释放依赖的步骤迭代至无新增删除，再排空共享正文队列。
每个正文回收批至多 512 行或 8 MiB，逐批提交并释放写协调；故障不中止其他独立清理步骤，已提交工作可恢复。

### 水位与引用判活

水位只推进已成功登记候选的期限区间。旧行即使长期被引用，也不在每轮重复全量检查；未来失去最后引用时会在删除事务中重新登记。
缩短保留期可能使下一轮处理大量首次到期行；延长保留期或时钟回拨可回退水位，不会因此把仍有引用的对象删掉。

| 竞态 | 不变量 |
| --- | --- |
| 写入准备期间候选正文已被回收 | 存在性提示非权威，引入新引用前重新取得或插入正文 |
| 候选入队后获得新引用 | 锁内重检保留仍在使用的对象 |
| 滑动映射检出时间推进 | 向未来扫描范围移动；若已在队列，领取时重新校验新时间 |
| 回收批中断 | 删除与依赖释放按事务提交，待办保留在持久队列，不复活半删除节点 |

### 并发与锁

- **SQLite**：在共享写协调和 `BEGIN IMMEDIATE` 内做存在性和引用裁决；解码、摘要等独立工作尽量不占用写租约。
- **PostgreSQL**：正文不用全表锁。写者用 `FOR KEY SHARE` 复用现有内容，插入用 `ON CONFLICT DO NOTHING`，冲突后核验锁定行；GC 用 `FOR UPDATE … SKIP LOCKED` 有界领取并重检引用。
- **依赖发布与回收**：必要的事务级咨询锁协调节点、Marker 与原生登记回收和依赖发布，避免不同更新顺序形成锁环；排队候选不是可跳过复检的理由。完整锁序见 [ADR-0089](../adr/0089-share-content-store-and-normalize-observation-writes.md)。

## SQLite checkpoint 与耐久性

共享连接池启用 WAL 和外键约束，保留 `synchronous=FULL`。
每个新连接按实际页大小换算 **32 MiB** 自动 checkpoint 触发窗口，4 KiB 页对应 8,192 页。窗口允许重复更新同一页的有界事务合并部分回写，不推迟 WAL 的提交同步。

该阈值不是 WAL 大小硬限：大型事务和长期 reader 可推高 WAL。页缓存与 mmap 配置不是预分配，也不计入派生缓存额度。
升级和离线维护有各自连接生命周期；不通过降低 `synchronous`、关闭完整性校验或把 checkpoint 移出测量窗口换取速度。

### SQLite 读写资源边界

实际读路径使用 `temp_store=MEMORY`、每连接约 16 MiB 的页缓存上限和最多 128 MiB 的 mmap 窗口；共享连接池的并发和实际工作集共同决定内存占用。
checkpoint 的记账单位是 page payload，不把 WAL 头、在途页或读者阻止回收造成的增长误称为超预算。维护不依赖缩小提交的同步范围。

## 升级迁移原则与约束

[ADR-0073](../adr/0073-cutover-to-single-baseline-schema.md) 固定 `0001_baseline.sql` 为两个后端的兼容起点。
空库可以初始化；已有库的迁移记录必须是连续、成功、checksum 可验证的前缀。只有完全相同 SQL 的 LF/CRLF 表示差异能在 runner 内消解，不能重写持久 checksum。
不修改已发布迁移，不接纳迁移历史未知的非空库，不遇错清库或自动修复不满足的新约束。

- **分阶段**：先准备 schema，再转换和验证，确认成功后才切换并删除旧结构；正常运行不保持双格式读取。两个后端独立迁移，业务约束一致。
- **有界批次**：按记录数和逻辑字节限量，先以薄元数据选连续前缀，允许首个不可分单元独占一批；复用批读和共享正文。可并行的解压、摘要、解析由有界 worker 准备，SQLite 保留单 writer 和迁移锁。
- **可恢复**：提交前失败只回滚当前批；重启从已提交进度继续或幂等重查。不允许跳过校验而提前删除旧结构，也不在每次启动重跑已完成阶段。
- **真实进度**：只有数据库批提交或文件可靠落盘后才增加完成量；DDL、锁等待等未知工作量保持不定进度，不用阶段权重或耗时伪造百分比。Server 与 Desktop 的就绪与中英文显示见[启动与迁移进度](admin-auth-bootstrap.md#启动与迁移进度)。

SQLite 普通已升级启动只校验迁移历史和外键启用状态，不做全库 `foreign_key_check`。表重建、数据转换及未审核迁移保留必要的全量检查；明确审核的增量步骤（含纯新增表/列/索引及无入站外键依赖的表重建）可跳过无关扫描，但不关闭约束。
历史数据转换钩子按各自终结迁移版本门控（已高于终结版本的存量库直接跳过），避免每次跨版本增量升级重复探测已退役格式。
共享内容存储转换（`content_store`）、Observation 形态规范化（`observation_data`）、凭据映射清理（`credential_cleanup`）与 Generation 前缀索引重建（`history_index`）均采用批读批写与跨批有界缓存：

- `history_index`：稳态启动先执行零写锁存在性检查，无旧命名空间节点即直接返回；存在旧节点时按 128 节点批读、跨批 64 MiB 逻辑预算缓存共享正文、仅恢复前缀折叠所需的客户端输入/输出槽位（缺失 `client_output` 时回退 `effective_output`），在写锁外完成解码折叠，再按批短事务写回并在提交后推进真实进度，中断后可从剩余旧节点幂等续跑。
- `credential_cleanup`：启动清理仅解析并规范化内置规则目录的 ID 集合（不编译检测正则、Aho-Corasick 或分词器），待清理总量为 0 时提前退出，写回与删除均按批提交。

离线复制只搬迁受支持的数据根并核验副本，不修改源 schema；目标启动补齐尚未应用的迁移。回退依靠恢复升级前的配套备份，不用旧二进制读取新结构。

迁移编排由 [Core migrations](../../backend/crates/stravia-core/src/migrations.rs) 持有；更新迁移时由 `stravia-tools dump-schema` 生成两份参考 SQL，不手改导出。
指标必须区分处理阶段、后端、负载、CPU、RSS 和实际 I/O，不能把逻辑预算或单条 SQL 当成产品性能。历史协议基准及测量限制见[跨协议 HTTP 基准](../research/protocol-http-benchmark.md)。

### 启动与失败结算

| 阶段 | 已提交事实 |
| --- | --- |
| 准备连接与历史校验 | 检查基线范围和已应用历史，不运行 Gateway 后台任务。 |
| 有数据的转换批 | 同事务提交批内引用与其恢复信息；事务回滚不增加进度。 |
| 无可靠总量的结构操作 | 报告当前阶段，无虚构分母；即使上一阶段完成也不代表业务可用。 |
| 切换完成 | 只在转换、校验和迁移全部确认后开放依赖新结构的服务。 |

宿主由 `Gateway::prepare` 得到仍持有池的 `PreparedGateway`。首次设置与普通启动用同一准备结果检查管理员后再启动，不为同一次启动重复建池、校验及迁移。
共享正文或引用回填的代价随唯一内容、受影响节点和引用数增长；同批避免重复解码公共正文，但不能略过某条独立引用的 scope 或摘要检查。
无关运行期请求不能从迁移未完成的实例得到伪成功；失败不通过取消耐久设置自动重试。备份可作为回退，不代替验证。

## 已否决技术选型

| 选型 | 未采用的原因 |
| --- | --- |
| `sonic-rs` | `serde_json` 任意精度和 `RawValue` 互操作不能保持所需语义；共享子树还可能钉住整块 arena，难以可靠计量。 |
| `EcoString` | 已拥有的 `String` 到平台文本的边界反而多次复制；现行 `Arc<String>` 可接管旧缓冲并在需要时共享。 |
| `Foyer` | 磁盘层增加恢复、解码、校验和写入开销；减少正文 SQL 不等于改善端到端延迟，保持 TinyUFO / Redis。 |
