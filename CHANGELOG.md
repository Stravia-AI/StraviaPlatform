# Changelog

## Unreleased

### Added

- Account-level allowance items can now be guarded per model service. Exhausted guarded items persistently pause that service's Targets across all Routes without changing administrator enable switches; successful fresh reads or removing the relevant guards restore routing. Known reset times trigger a read rather than promising recovery. The allowance page, model-service screens, and Target badges show the pause evidence; requests whose candidates are all paused receive a native quota error (HTTP 429, without `Retry-After`).
- Added `task test:all` for the complete local Windows test matrix, including real browser and desktop smoke tests, isolated PostgreSQL, incremental-build checks, and cleanup. The command reports per-suite logs and fails if tests fail or the end-to-end run exceeds five minutes; initial cold builds are not covered by that time target.
- Desktop and Server startup screens now show the current operation and real per-phase migration progress. Unknown totals use an indeterminate bar instead of a simulated percentage. Server exposes the startup screen before database preparation finishes, while business APIs and health/readiness probes remain unavailable until preparation completes; existing management entry restrictions and authentication remain in force.
- Credential Protection now supports custom rules. Add an exact-text rule (a request containing the text is replaced and restored like any detected credential) or a pattern rule with a regular expression, capture group, keywords, and minimum entropy. The rules table can be filtered by Built-in or Custom, and the match test includes enabled custom rules. Deleting a rule does not remove mappings it already created; they remain restorable until they expire.
- Added the dedicated `claude-code` Vendor Plugin for Claude Pro/Max subscriptions. It is published as a standalone release asset for local import; sign in through the browser to use subscription models through the Anthropic Messages API, with model discovery and 5-hour, weekly, and extra usage allowance monitoring. Requests are sent in the Claude Code CLI format, and the reported CLI version can be changed in the connection's advanced settings. Using a subscription outside Claude Code may violate Anthropic's terms and can get the account restricted. Connections on the removed `anthropic/claude-code` channel are not migrated; create a new `claude-code` connection and rebind its Routes.

### Changed

- Vendor SDK WASI interfaces now use 0.2.12. The host accepts stable 0.2.x versions of the existing restricted interface set, including mixed patch imports, so compatible installed plugins do not require rebuilding. Prereleases and other major/minor versions remain rejected; required functions and resource types must still match the host. The `stravia:vendor@0.4.0` contract is unchanged; filesystem, raw sockets, and WASI HTTP imports remain forbidden.
- **Breaking:** Removed the standalone observation `/interactions/{id}/summary` management endpoint and client API. Selected interaction details and failure-to-chain navigation now use the interaction detail resource and existing root reveal; internal summary reads remain part of detail construction.
- **Breaking:** Request History now separates lightweight global observation notifications from the selected interaction's live-body SSE subscription; consumers of `/api/v1/observations/events` must use change metadata and fetch durable timeline facts on demand. Root updates use `/api/v1/observations/interactions/changes` with explicit removals and snapshot resets instead of repeatedly transferring unchanged siblings. Root/detail/failure refreshes are coalesced, Debug state is read in batches, and intermediate live revisions use bounded latest-wins publication with immediate first/terminal handling. Selected conversation, expanded Thinking, and selected canvas output share grapheme-aware rendering; publication, refresh and reveal share a 500ms scheduling-wait budget (100/100/300ms), not an end-to-end latency guarantee. Authentication, inference delivery, Canonical Item persistence, usage, failure classification, and Debug Bundle contents are unchanged. See the [observation contract](docs/design/interaction-observation.md).
- Provider model details now include a directly editable RPM form. Model catalog context, modalities, reasoning effort, and availability cells can be edited in place; specification edits preserve unrelated metadata and pricing and retain revision-conflict protection.
- The allowance page now uses one read-coordination module for credential gating, manual refreshes, and guard saves. Failed saves retain confirmed guards, missing guarded keys survive edits, and canceled older reads cannot overwrite saved results. Existing polling, caching, layout, and feedback remain unchanged.
- **Breaking:** Model pricing now keeps only input, output, cache-read, and cache-write rates across base, extended-context, and tier prices. Removed reasoning, audio-input, and audio-output rates from metadata, administration, and storage; SQLite/PostgreSQL migration 0013 removes saved values and projection columns while preserving the remaining decimal prices. Back up the database before upgrading; restoring removed rates requires that backup. Reasoning settings, audio modalities, and usage records are unchanged. Model screens now use “Reasoning effort” / “推理强度” consistently.
- **Breaking:** RPM limits and shared-pool membership now belong to Provider/upstream-model destinations, not Route Targets. Choose an own limit or a shared pool in the Provider model catalog; edit pool names and limits in Model services.
- **Breaking:** Every Route Target, including external Web Search, now requires a nonblank upstream model and the corresponding Provider Model capability. Missing or null target models are rejected. SQLite/PostgreSQL migration 0012 deletes legacy model-less Targets and model-less `rpm_admission` destinations without inventing model IDs; Routes remain. Rebind affected Routes to real Provider Models before using them. Vendor SDK channel descriptors no longer expose the search model requirement flag; third-party Rust descriptor constructors must be updated, while the WIT ABI is unchanged.
- **Breaking:** Removed shared RPM pools, their management UI, destination bindings, and runtime counting. RPM limits belong only to Provider/upstream-model destinations, configured in the Provider model catalog; the same destination still shares its window across Routes. SQLite/PostgreSQL migration 0014 removes stored pools and bindings without copying pool limits: former members become unlimited, while independently configured limits and queue settings remain. Set individual limits for former members before reopening traffic if required. The settings API rejects the removed `pools` and `rpm_pool_id` fields.
- Local test builds now preserve separate executables for incompatible feature graphs, and storage E2E uses a workspace-built harness instead of compiling a temporary Cargo project for each scenario. Parallel PostgreSQL storage workers use separate databases to avoid sharing database-scoped migration locks; actual migrations and reconnect checks remain unchanged. Ordinary SQLite fixtures reuse a once-migrated database image while retaining independent writable databases and dedicated migration, restart, concurrency, TTL, and large-payload checks.
- All Rust crate package and dependency versions, including Wasm regression fixtures, now inherit the root workspace manifest and share the root lockfile. Target-specific features remain in crate manifests; incompatible upstream version families remain separate rather than being forcibly replaced.
- Desktop and standalone Server builds now align shared runtime, build-time, procedural-macro, and platform-binding dependency features to improve cache reuse when switching entry points. Server WebUI embedding remains separate, and standalone Server does not acquire the desktop runtime. Default Gateway, Provider Catalog, and S3 HTTP clients explicitly connect directly instead of inheriting ambient proxies; configured Provider proxies remain supported.
- Development and test builds now use limited debug information for third-party dependencies to reduce PDB size and incremental rebuild cost, while workspace crates retain full debug information. Optimization levels, incremental compilation, and release profiles are unchanged; dependency variables can be debugged with a package-specific debug-info override.
- **Breaking:** API-key `concurrency_limit` is replaced by nullable `rpm_limit`: strict sliding 60-second root-request RPM, not active-stream concurrency. Proxy, compaction and MCP execution share the key window; rejection returns 429 with `Retry-After`. SQLite/PostgreSQL migration 0009 clears every old limit to `NULL` without conversion: requests are **unlimited until administrators set new RPM limits**. Upstream retries and hidden turns each pass the actual-send RPM gate for their Provider/model destination. Destination limits default to unlimited; preferred/total waits default to 5/30 seconds and the instance queue to 128 waiting roots, not active streams. Runtime windows reset on restart and do not coordinate across instances. Confirmed request-parameter/context/content errors no longer poison shared Target health; eligible roots retain one RPM-controlled cooldown attempt per Target. See [configuration and migration](docs/design/architecture.md#84-上游目的地-rpm-发送门禁与配置).
- Generation history now stores Principal-scoped, content-addressed JSON Items with shared zstd/raw binary encoding. Repeated instructions, messages, tool results and Agent transcripts share content without changing payload v6, Item metadata, references, strict continuation checks or retention. Startup converts supported legacy history losslessly; back up the entire data directory and any external PostgreSQL database before upgrading. Rollback requires restoring that backup, not opening the converted schema with an older binary. Existing SQLite files are not automatically vacuumed.
- Debug manifests and state now live only under the owning instance's `diagnostics/observation-debug/` directory. Database-only replicas cannot display those traces. Clear Debug retires in-flight captures before deleting their files; new captures remain available. Migration exports existing manifests before removing their database source.
- SQLite history and ordinary observation writes now share an asynchronous write gate instead of competing in the busy handler; reads and Debug file I/O remain outside the gate. Debug manifest updates retain the first completion and expiry, skip only successfully persisted identical terminal states, and accept safely pre-created trace directories without overwriting segments.
- Canonical source parts use ordered category/index identities on both native and wasm32 targets, preserving reasoning summary/content order without platform-width overflow or large-index collisions.
- Ordinary thinking diagnostics retain canonical item references without retaining protected wire snapshots or unknown metadata extensions. Non-thinking and already-published items no longer allocate discarded thinking snapshots.
- Ordinary observation payloads now use the shared binary codec, and verified request deltas avoid repeated client tool-result captures. Conversation content is saved once per Canonical Item, with immediate first/terminal live previews, bounded intermediate publication, and retained partial Items on handled failures. Usage is merged into `target_attempt_finished`; delivery and output commitment are merged into `run_finished`. The event API removes redundant lifecycle/debug signals and persisted content deltas. Numeric usage projections remain immediately queryable; timeline usage arrives at attempt completion, and late terminal facts use new immutable sequence IDs. See the [observation contract](docs/design/interaction-observation.md) for cursor, Bundle and migration semantics.

- Request preparation now queries the controls-history fallback only when no session candidate passes strict verification, and reuses verified materializations for reference-free parents. Observation event batches allocate sequence IDs in one database call, while route selection reuses Provider Model prices until a local configuration write or config-epoch invalidation. Usage and invalid-credential evidence are still read for every selection. Principal/TTL checks, ancestor references, event ordering and cursors are unchanged; no database migration is required.
- Long-history parent discovery now uses indexed fingerprint/item-count pair lookups, restores shared content once per unique Principal/key in each batch, and reuses immutable materialization cache entries without copying whole histories on cache hits. Cache byte accounting no longer allocates a complete JSON buffer. Strict canonical-prefix verification, candidate ordering, Principal isolation, TTLs, and corruption checks are unchanged; no database migration is required.

- The allowance page now shows each model service as one compact row with every allowance item's value and meter; click the row to expand reset times and per-item settings. Values show what remains by default, and a Remaining/Used switch changes every percentage at once and is remembered on this device; account balances always show the balance. The guard switch is now labeled "Pause when exhausted" with an explanation of its routing effect, and items with it on are marked in the compact row.
- Model modalities (text, image, audio, video, PDF) now appear as icons wherever a model's input and output types are shown, with the name on hover and for screen readers; unrecognized types use a generic icon with their raw name. Modality filters and the model editor's type picker show each icon next to its name.
- Model screens now use compact desktop tables and narrow-screen lists, with copyable client model IDs, context, request destinations, and enabled state. The destinations column summarizes the highest-priority layer that still has a usable destination (model name and service, or destination count and scheduling strategy), then counts skipped layers, fallback layers, and unavailable destinations for any number of layers; usability reflects service enablement, invalid credentials, and allowance pauses, while cooldown stays in the model editor. Admin Route Targets now include a read-only `model_name` projected from the Provider Model snapshot, or `null` when no name is registered. Provider model catalogs and filters show context, input/output modalities, and explicitly supported effort values. Specification editors use one effort selection instead of reasoning-type groups; model details present structured pricing. Destination cards retain priority lanes, drag-and-drop, and runtime status, with context and modalities below the model and service identity.
- **Breaking:** Model token limits now keep only `limit.context`, and reasoning specifications use a `reasoning_efforts` string list. Removed the five supported-feature flags, `interleaved`, input/output limits, and toggle/budget reasoning specifications; requests still support native attachments, reasoning, tools, structured output, sampling, and output-token controls. Targets retain explicit native toggle and budget controls. Model declarations no longer gate function-tool eligibility. Missing efforts generate hidden thinking mappings rather than guessed defaults. SQLite and PostgreSQL upgrade existing data without resetting connections, route bindings, or Target mappings; explicit re-import refreshes Generated mappings and preserves overrides. Client configurations no longer export model output-token limits.
- The Devin Vendor Plugin now prioritizes compatibility by dropping unsupported optional request controls before validation, including tool choice, parallel-call controls, seed, stop sequences, penalties, structured-output requests, and protocol-specific generation options. Devin's native behavior applies instead: callers must not rely on these constraints being honored. Message content, safety settings, and data-location constraints are not silently removed by this policy. Other Vendors are unchanged; update the standalone Devin plugin to receive this behavior.
- HTTP requests from the embedded base Vendor now carry an `x-session-id` header that stays the same for every turn of a conversation, so upstreams that route prompt caching by session (such as OpenRouter) can keep a conversation on the same cache node. Stravia derives the value from its own conversation tracking rather than from client-supplied session IDs; a new conversation gets a new value. The OpenCode Zen `x-opencode-session` header now follows the same conversation value instead of changing on every request.
- Request History Conversation and Diagnostics views now open at the latest content and follow new events while you stay at the bottom. Scrolling to the top shows a loading indicator and loads earlier events in place without shifting what you are reading. Diagnostics no longer shows earlier runs as empty before their events load.
- Request History Diagnostics now collapses each run to a summary by default. Under the run title, two lines show the upstream model and model service that served it, duration, time to first token, and token speed, followed by input, output, cache-read, and cache-write tokens; unreported values show a dash. Expand a run to see its identifiers and event stream. Incomplete-recording warnings stay visible while collapsed. Run titles no longer show status, interruption, or Debug badges: the timeline marker's shape and color show the run status, interruptions appear in the event stream, and Debug capture status remains in the interaction overview.
- `claude-code` model discovery now reads native capabilities and context from Anthropic's `/v1/models`. After syncing models, the Thinking Level Map shows explicitly declared effort levels (including `xhigh` and `max`); native thinking and context-management constraints remain enforced. Model output limits are no longer registered or used to cap requested `max_tokens`. New Claude models work without a plugin update; connections that have not synced models yet keep using the built-in native thinking rules.

### Fixed

- Provider model editing now protects unsaved specifications during in-app and browser-history navigation or manual-draft closing. Pending model writes lock conflicting edits and navigation; late detail or preparation replies cannot replace or reopen another editor. Successful writes retain their returned revision when related refreshes fail, and Retry refreshes without resubmitting. Selecting an existing model through the manual-template entry preserves its saved specifications and revision.
- Usage analytics now use the same final-request failure classification as Failed Requests. Error counts in overview, time buckets, and model-service summaries exclude recovered retries, cancellations, disconnections, interruptions, and active requests; retain admission rejections and final failures after successful model output; and count each client request once rather than each hidden turn or attempt. Request counts and error-rate denominators in those views now use the same client-request units. SQLite and PostgreSQL apply the same retention and request-start-time rules; stored attempt diagnostics and token usage are unchanged.
- Data-table scrollbars now sit outside the data viewport instead of covering cells. The Model services table fills the remaining page height, while Connect client and code previews fill wide split layouts and retain a 24rem minimum height in stacked layouts.
- OAuth model services now offer **Reauthorize** in their action menu, restarting the existing sign-in flow and binding the new credential without changing saved connection settings. Allowance monitoring shows when an invalid credential prevents fetching and pauses automatic and manual upstream reads for that service until the credential is repaired; other services continue refreshing, and any last successful result is marked stale.
- Fixed stale protocol/UI fixtures, terminal-observation races, and Windows desktop-driver setup and teardown in the test suite. Deadline interruption now expires the actual shared deadline instead of advancing an unrelated fake clock, removing an unintended five-minute wait without changing product timeouts. Renewal tests no longer depend on millisecond-scale scheduling; layout checks use one geometry snapshot, and test clients send complete buffered HTTP requests to preserve early authorization responses on Windows.
- Interaction Debug Bundles now preserve confirmed token fields when late usage revisions omit them, without counting the same attempt twice. Bundle snapshots are derived directly from events at the ticket watermark; ordinary request-history queries, archive layout, and download-ticket behavior are unchanged.
- Fixed slow startup upgrades of large history and observation databases. Legacy history-reference and Run lookups now use migration-only indexes, avoiding repeated Principal-wide reference scans on large SQLite databases, and lifecycle merge candidates are filtered before decoding; history preparation, observation decoding and Debug manifest exports use up to eight blocking workers. Database commits remain ordered and resumable, and startup logs report migration stages and committed progress. Existing migration checksums and the final schema are unchanged.
- Gemini-generated media streamed as completed Items now retains its Canonical Item identity, preventing an accumulator panic and incomplete-stream error while preserving media signatures and reusable Artifact References.
- Fixed thinking-history replay when a Route switches Targets internally without changing the client-visible model. Open Responses, Anthropic, Gemini, and OpenAI-compatible requests retain readable thinking and tool associations without treating another protocol's signature as native ciphertext. Responses reasoning input now keeps its full readable content in adjacent assistant text while leaving the native reasoning input content empty. Derived assistant messages and tool calls no longer inherit the source thinking item's ID or native metadata, preventing item-type/ID mismatches after failover. Gemini native tool signatures return on their original function-call part, including streaming replay.
- Imported tool history can continue on official Google Gemini 3 and 3.x `generateContent` endpoints using Google's documented missing-signature migration control, without replacing genuine signatures. This does not restore private reasoning and is not enabled for Vertex, custom base URLs, unknown latest aliases, or unverified API paths; those endpoints may still reject unsigned current-turn tool history. See [Thinking Replay policy](docs/adr/0075-replay-protected-reasoning-within-protocol-and-learn-rejections.md).
- Vendor transport failures now retain the underlying error cause chain in redacted logs and failed-request diagnostics, so WebSocket failures distinguish abnormal closes, protocol errors, and I/O failures instead of reporting only "tungstenite error". Retry, continuation, timeout, and wire-capture behavior are unchanged; missing causes in historical records cannot be recovered.
- Requests no longer wait until a 504 when an upstream rate-limit `Retry-After` cannot fit within the remaining request window. Model inference and independent capability calls try an eligible backup Target immediately, or return the original upstream error when no backup is available; they do not shorten the upstream wait and retry early.
- Explicit Claude subscription allowance exhaustion now triggers Target failover instead of same-Target rate-limit retries. Ordinary rate limiting and incomplete allowance evidence retain their existing classification. Update the standalone `claude-code` plugin as well as Stravia to receive the classification fix.
- Raised each Vendor attempt's pre-output event buffer budget from 1 MiB to 16 MiB so large Codex tool-schema echoes can be retained before the first output. The buffer remains bounded and still fails explicitly when its budget is exceeded.
- Image requests and tool results no longer fail with "Vendor operation input was rejected" when forwarded to Anthropic or Google Gemini because they include an image `detail` hint. Targets without an equivalent control omit the hint while preserving the image and tool-result association; OpenAI-compatible and Open Responses targets continue to receive it unchanged.
- Codex OAuth now presents client version `0.159.2` on model discovery and generation requests. The upstream lists `gpt-6.1-sol` only for recent client versions, so connections pinned to `0.156.1` may not have shown it; rediscover models on existing Codex connections to pick it up.
- The `claude-code` Vendor Plugin now always places prompt-cache breakpoints itself, the way Claude Code and oh-my-pi do, and discards any `cache_control` the client sent: one on the last tool, one on the last system block, and up to two on the conversation tail (plus a checkpoint every 15 user turns), never more than four, all with a one-hour TTL. Requests arriving through OpenAI-compatible, Responses, or Gemini entry points previously reached Anthropic without any breakpoint, so cache reads and writes stayed at zero. Client-chosen breakpoint positions and TTLs are no longer honored by this plugin.
- The `claude-code` Vendor Plugin no longer fails with "`temperature` may only be set to 1 when thinking is enabled or in adaptive mode". Like Claude Code, it now omits `temperature`, `top_p`, and `top_k` when thinking is on or the model (Opus 4.7 and later, Sonnet/Fable/Mythos 5 and later) rejects custom sampling, and drops request fields Claude Code never sends (such as `service_tier` and `container`). Thinking settings are now also adapted to the Claude model in use, so OpenAI-style reasoning effort no longer produces requests Anthropic rejects: models that only accept adaptive thinking (Opus 4.7 and later, Sonnet 5 and later, Fable/Mythos) receive `adaptive` plus `output_config.effort`, budget-only models (Claude 4.5 and earlier) receive a thinking budget with `max_tokens` raised to leave room for it, unsupported effort levels are lowered to the nearest supported one, turning thinking off follows each model's rules (models that cannot disable thinking get the lowest effort instead), and a forced tool choice no longer conflicts with thinking. Adaptive thinking on Opus 4.7 and later requests summarized thinking unless the client chooses otherwise, and an OpenAI `reasoning.summary` value (`auto`, `concise`, `detailed`) is sent as `summarized` instead of being rejected as an invalid `thinking.display`. Rebuild and reimport the plugin to pick this up.
- The `claude-code` Vendor Plugin no longer fails with "`thinking.adaptive.display`: Input should be 'summarized', 'omitted'" when an Open Responses request sets `reasoning.summary` to `auto`, `concise`, or `detailed`; these now request summarized thinking and any other value is dropped.
- The Observation "Model output preview" now starts a new paragraph for each model turn instead of running the text of consecutive turns together. Previews recorded before this change keep their existing text.
- Anthropic Messages requests forwarded to an Anthropic-protocol upstream now keep tool `strict` flags and `tool_result.is_error` (including `false`). Routes to other protocols behave as before.
- Vendor Plugins can now send `Connection: keep-alive` and negotiate `Accept-Encoding`. When a plugin sends `Accept-Encoding`, Stravia decodes gzip, deflate, Brotli, and zstd responses before handing them to the plugin. Plugins that do not send it, including already installed older plugins, receive responses unchanged.
- Signing in with the `claude-code` Vendor Plugin no longer fails on the claude.ai consent page with "Authorization failed: Invalid request format". Vendor Plugins can now choose the OAuth `state` value when the upstream requires a specific format; plugins that do not, including already installed older plugins, keep using the state Stravia generates. The updated `claude-code` plugin requires this Stravia version.

## [0.3.1] - 2026-09-29

### Removed

- **Breaking:** Removed the Anthropic `claude-code` OAuth channel, including subscription sign-in, token refresh, curated model discovery, and allowance monitoring. Anthropic API-key access and Claude Code client configuration remain supported. Existing subscription connections, credentials, and history are retained, but the removed channel is unavailable; configure an Anthropic API-key connection and rebind its Routes to resume inference.

### Added

- Debug now collects process CPU/RSS, SQLx query and connection-acquisition histograms, named execution timings, and observation queue/cache gauges. A single tracing span pipeline supplies both Prometheus aggregates and a bounded Chrome Trace JSON timeline, downloadable by administrators from Settings without another listener. The timeline preserves async parent relationships, reports dropped and incomplete spans, and does not pretend to be a CPU profile. SQL text and request contents are excluded from performance exports.

- Cline Pass is now served by the embedded base Vendor's `cline-pass` catalog Profile — standard OpenAI-compatible access with API-key authentication plus subscription allowance monitoring — and no dedicated plugin package is built or required. A `clinepass` plugin previously imported from a local package is not migrated or uninstalled automatically; recreate the connection as a base `cline-pass` Provider, rebind its Routes, then uninstall the old plugin in **Vendor Plugins**.

### Changed

- Updated compatible Rust and WebUI dependencies, including Tauri 2.11.2, Wasmtime 49, RMCP 3.5, Svelte 5.57, and Vite 8.3.

- The single Debug switch and Debug Trace cleanup action now live in Settings → Diagnostics instead of Request History. The switch controls performance sampling and wire capture together, requires confirmation when enabled, and resets after restart. Disabling freezes performance data, marks active spans incomplete, and preserves the capture decisions of in-flight requests.

- Supported Thinking Levels now use the union of non-hidden mappings across enabled Route targets instead of their intersection. The model editor, model discovery, client configuration exports, and Media Understanding level selection expose a level when at least one enabled target supports it. Disabled targets remain excluded; runtime matching still uses the selected target's own mapping.

- Protected reasoning now survives account, deployment, and proxy changes within the same protocol unless the destination has already rejected that payload. Cross-protocol replay and Gemini model changes still strip incompatible protected reasoning. Rejections trigger at most two pre-output recovery requests without consuming the Target retry budget or putting the Target into cooldown; successful recovery remembers rejected payloads until restart. These additional upstream requests may consume provider quota.

### Fixed

- Desktop performance exports now report the saved file path after the native download completes, or show a cancellation/failure message instead of silently saving files without feedback.

- History restoration avoids repeated ancestor reads and unrelated SQLite reference scans, reducing cold-cache work for long conversations without changing stored history or replay semantics. Performance exports now attribute SQL timings to named operations and include cache hit/miss counts and timeline work measurements.

- The bundled base plugin now updates on startup when its version is unchanged but its component digest differs, including when the previous bundled artifact is unavailable. Identical components are not reinstalled; downgrades and locally installed replacements remain excluded from automatic updates.

- Startup recovery now uses run/status indexes for Model Turn and Target Attempt observations on SQLite and PostgreSQL, avoiding repeated full-table scans as request history grows. Existing databases receive the indexes through an incremental migration without deleting history.

- Overview and Usage analytics latency charts now use actual timestamps for horizontal positions, preventing lines from doubling back when a 24-hour window includes the same clock time on consecutive days. Localized axis and tooltip labels and gaps for periods without requests are preserved.

- The request-history model filter now lists each Route by its effective display name and shows the same name for the applied selection, so Routes without a display name appear by Model ID instead of exposing the internal Route ID or reading as "All". Filter requests still send the Route ID unchanged.

- Interrupted interaction chains retain their last request activity time instead of reappearing in recent activity when a delayed disconnect, idle timeout, restart recovery, or terminal cleanup is detected. Diagnostic events still record the actual detection time; previously stored timestamps are not backfilled.

- Client-owned tool arguments now remain verbatim across Chat Completions and Responses delivery, streaming completion, stored history, and client replay, including empty or malformed JSON. Response hooks no longer fail a completed upstream call solely because client arguments are invalid; platform tool argument errors instead return an error tool result without executing the tool. Credential protection retains decoded-string handling for incomplete JSON and fails closed when outbound escapes cannot be safely interpreted. Object-only protocol conversions reject unrepresentable arguments rather than fabricating empty objects.

- Command Code and other known plugin-owned protocols now apply target-specific thinking-history replay independently of host codec registration. Client-replayed Responses reasoning no longer causes a local HTTP 400 after history compaction or edits; readable reasoning and tool-result associations are preserved without relaxing protocol validation or history matching.

- Replayed reasoning is no longer turned into ordinary assistant text on targets whose native reasoning field accepts unsigned reasoning, such as Chat Completions `reasoning_content` and Command Code. Previously the model could treat that reasoning as text it had already said and stop producing reasoning. Anthropic, Bedrock, and Responses history without a replayable reasoning id still falls back to text.

- Protected-reasoning recovery first removes only unverified reasoning, then all protected reasoning if necessary. Anthropic, Bedrock, and Gemini signature rejections now trigger this recovery.

- Chat Completions upstream requests no longer include internal gateway request fields (`__stravia_*`, such as the generation session ID) in the request body.

## [0.3.0] - 2026-09-26

### Added

- Windows NSIS installers now include English and Simplified Chinese. The first interactive install offers a language choice defaulting to the Windows UI language when it matches; later installs and uninstalls reuse the saved choice. Passive updater installs still skip wizard pages and reuse a saved installer language.
- `StraviaRead` now extracts Office documents — docx, xlsx, pptx, doc, xls, and ppt — to paginated Markdown snapshots, with ZIP central-directory preflight, container magic validation, and encrypted-CFB identification; all CPU work runs on the blocking pool under cancellation and deadlines. Embedded images deduplicate by content bytes into Artifacts (decodable ones normalized to JPEG, originals retained with a recorded limitation), and image markers in the Markdown resolve to `sa:` links. `?question=` routes documents through Media Understanding, `?download=1` downloads without parsing, and `?raw` is explicitly rejected.
- Devin Provider support uses the `devin-connect` Connect-RPC protocol with binary Protobuf streaming, an OAuth PKCE authentication driver, model discovery, allowance monitoring, and usage parsing that reports cached and reasoning tokens. Devin model families aggregate related selectors into one logical model record; request content redaction neutralizes competing-vendor identity fingerprints, and selector matching covers speed lanes and the 1M-context tier.
- Command Code Provider support (`command-code`) ships as a built-in catalog Provider with NDJSON streaming, CLI envelope encoding, and allowance monitoring that chains whoami, credits, subscriptions, and summary calls to report window quotas, point balances, and billing periods.
- Vendor Options let Providers declare non-secret behavior toggles such as zero data retention; the WebUI provider editor renders them dynamically and persists them per Provider.
- Routes accept a default thinking level applied when the client does not specify a reasoning instruction, clamped at runtime to the Route's Supported Thinking Levels. The model editor exposes the default with validation, and unrepresentable thinking controls degrade to Hidden on read instead of guessing wire shapes — explicit submissions of unrepresentable controls still fail with `THINKING_CONTROL_UNREPRESENTABLE`.
- Usage analytics gains a `/stats/series` endpoint with caller-selected bucket size and timezone offset aligned to local wall-clock time, a token-activity heatmap that adapts columns to container width, per-Provider average output speed, and pie charts for model distribution and input/output/cache-read/cache-write token composition.
- Provider allowances load tiered and asynchronously: the list returns targets immediately while background fetches resolve each snapshot, concurrent requests for one Provider coalesce, and the WebUI renders the shell first with per-Provider loading and error states before the aggregate view resolves.
- DeepSeek balance reporting now surfaces CNY and USD accounts as separate currency-keyed rows, filters exhausted balances, and retains one USD record when the account is fully depleted.
- The desktop client's settings are consolidated under Client Settings: a LAN-binding toggle switches the gateway listener between `127.0.0.1` and `0.0.0.0` with a retry loop that shrinks the rebind window, silent start and launch-at-login preferences control whether the main window appears on startup, and the external address display offers one-click URL copy.
